# Security review v0.4 (task 25-04)

Alcance: templates y archivos del proxy (`traefik.yml`, `acme.json`, dynamic config), exposición
del API de Traefik, superficie de inyección en la dynamic config, DNS checker, ciclo de vida del
env file, secret store y API, snapshot v2, formatos de `docker inspect`/`ps`, dependencias e
imágenes nuevas. Checklist: skill `noodara-security`. Fecha: 2026-11-01.

## Hallazgos

| ID | Área | Severidad | Estado | Mitigación / evidencia |
|---|---|---|---|---|
| M1 | API de Traefik | Media | Abierto (v0.5) | El entrypoint `traefik` (:9180) escucha en todas las interfaces del contenedor (`static-config.ts`) y el proxy se une a cada `noodara-net-<serviceId>` (`proxy.ts`): un contenedor de servicio puede hacer `GET noodara-traefik:9180/api` y leer la lista de routers (hostnames y service ids de otros proyectos; sin credenciales ni certificados). Desde fuera del host está cerrado: el puerto se publica solo en `127.0.0.1` (probe real en `proxy-templates.test.ts`: `<hostIp>:9180 refused`, `web_api 404`). Mitigación: red interna dedicada o `ipAllowList` en el router `noodara-api`, antes de exponer datos del proxy al AI. |
| M2 | Logs de runtime | Media | Abierto (v0.5) | El API de logs de contenedor crea un redactor vacío por request (`container-logs.ts`); los secrets de aplicación solo se registran durante el deploy (`secret-store.ts`). Una app que imprime su propio secret lo muestra en logs de runtime y su SSE. Noodara nunca lo escribe: es salida de la app. Mitigación: registrar los secrets en scope del servicio por request de logs; obligatorio antes de que el AI lea logs (v0.5). |
| L1 | Puertos publicados | Baja | Corregido | `RESERVED_PUBLISHED_PORTS` era `[22, 2375, 2376]`: un servicio podía tomar 80/443/9180 con el proxy detenido y bloquearlo o suplantarlo. Ahora incluye 80, 443 y `PROXY_API_PORT` → 422 `SERVICE_INPUT_INVALID` / `PUBLISHED_PORT_RESERVED` en create y edit. Tests: `packages/domain/src/project/service.test.ts`, `tests/integration/proxy/abuse.test.ts`. |
| L2 | Límites de secret | Baja | Abierto | `MAX_SECRET_VALUE_LENGTH` (64 KiB) > `MAX_ENV_VALUE_BYTES` (32 KiB): un secret grande se acepta pero todo deploy que lo referencia falla con `ENV_INJECTION_FAILED`. Falla cerrado, sin fuga. Mitigación: alinear límites en v0.5. |
| L3 | DNS checker | Baja | Abierto | El `Resolver` es compartido y el timeout llama `resolver.cancel()` (`domain-dns.ts`), que aborta también checks concurrentes (resultado `timeout`, reintentable). Timeouts 2 s/3 s y rate limit por dominio vigentes. Mitigación: un `Resolver` por check. |
| L4 | Env file | Baja | Corregido | `writeEnvFileFromStdin` no tenía `trap`: un SIGHUP (canal SSH caído) dejaba `env.tmp` (0600, con valores) hasta el cleanup del workspace. Ahora `trap 'rm -f -- "$0.tmp"; exit 1' HUP INT TERM`. Test: `packages/ssh/src/commands/shell-scripts.test.ts` (SIGHUP al grupo a mitad de escritura: sin temp, exit ≠ 0). |
| L5 | Cifrado at-rest | Baja | Abierto | AES-256-GCM sin AAD (`envelope.ts`): quien escribe en la DB puede intercambiar ciphertexts entre filas. Requiere acceso de escritura a Postgres. Mitigación: AAD con id de fila y tipo en la próxima rotación de formato. |
| I1 | `docker inspect` | Info | Aceptado | `Config.Env` del contenedor (y del `-prev`) contiene los valores: inherente a Docker. Noodara nunca lo lee: test estático de templates (sin `.Config.Env` ni `{{json .Config}}`), formatos de inspect limitados a `.State`, `.NetworkSettings.Networks`, `.Id`; el parser de `ps` conserva ID/Image/Names/State/Status/Labels/Ports. |
| I2 | Hostnames | Info | Aceptado | `toLowerCase` convierte el signo Kelvin (U+212A) en `k`; labels `xn--` no se validan como punycode. Ambos producen un hostname LDH válido, sin inyección. |
| I3 | Preflight de puertos | Info | Aceptado | Sin `ss` el preflight da `unknown` y la instalación sigue (falla en `start` con `PROXY_PORT_IN_USE`); un listener ajeno en 9180 también falla en `start`. Docker < 28: el publish en 127.0.0.1 es alcanzable desde hosts vecinos en L2 (comportamiento de Docker; mitigado por firewall del host). |
| P1 | Archivos del proxy | — | PASS | Dirs 0700, archivos 0600, escritura atómica con `.prev`; `acme.json` lo crea Traefik 0600 dentro de dir 0700; dynamic config por stdin, nunca interpolada. `api.dashboard=false`, `insecure=false`, sin telemetría. |
| P2 | Inyección en dynamic config | — | PASS | Hostnames LDH-only, normalizados y revalidados en el renderer (`PROXY_CONFIG_HOSTNAME_INVALID`); service id UUID; JSON canónico. Abuse test: comillas, backticks, saltos de línea, NUL, `@`, unicode, homoglifos, wildcard, path, esquema, puerto, IP → 422 `DOMAIN_INPUT_INVALID` con `reason`; >253 → 400; nunca llega al apply. |
| P3 | Env y secrets | — | PASS | Env file 0600 (umask 077) por stdin, tamaño verificado, borrado en `finally`; valores > 32 KiB → 400/422 `ENV_VALUE_TOO_LARGE`; `<secret:../x>` y variantes → `ENV_SECRET_REF_MALFORMED`; nombre `../x` → `SECRET_NAME_INVALID`. Snapshot v2 guarda solo `secretRef` + versión. |
| P4 | Imágenes y dependencias | — | PASS | Traefik fijado por digest y validado (`DIGEST_PINNED_IMAGE_PATTERN`, `env.ts`); pebble y challtestsrv fijados y en allowlist (`tests/integration/helpers/pebble.ts`). `pnpm audit --audit-level=high`: 0 critical, 0 high (16 moderate, 5 low). |

## Canary de secrets de aplicación (A2)

`tests/integration/activity/canary-env-secrets.test.ts` siembra un secret y una variable
`<secret:name>`, despliega `env-api`, recorre 10 rutas de error, rota y redespliega, provoca
`SECRET_UNRESOLVED` y borra. Busca el valor, su prefijo de 20 caracteres y su base64 en respuestas HTTP y errores, logs del
API y worker, excepciones, logs de deployment y chunks, logs de runtime, activity, SSE, Redis,
filas de deployments (snapshot v2) y toda salida SSH capturada (incluidos `docker inspect` y `ps`):
0 coincidencias. Superficies de prompt y respuesta AI: no aplican hasta v0.5.
