## Checklist `noodara-security` §10

- Secret como `string` fuera del cifrado: no; la key viaja como `SecretValue` y `revealSecret` solo ocurre en el provider.
- Schemas de salida: rutas AI, settings, logs, métricas y graph declaran `response` Zod (`ai.ts`, `ai-settings.ts`, `*-schemas.ts`).
- Timeouts y `error_code`: provider (P4), SSH de logs y collector con timeouts de `packages/ssh`; fallo del provider → evento SSE `error` + `status: failed` con mensaje fijo (canary AI).
- `ActivityEvent`: el canary AI escanea activity; al modelo solo llega la allowlist de `activityEntry` (`log-entries.ts`).
- Input a shell/path/query: los tools validan con Zod y llaman al backend tipado; no hay template nuevo con input del modelo.
- Borrado: `DELETE /api/settings/ai` (key) y `DELETE /api/ai/conversations/:id` (aborta, borra mensajes y tool calls).
- Test de fuga: `canary-ai.test.ts` (abajo).

## Threat model de prompt injection (H1)

Mitigaciones comunes a todo canal: resultado de tool en sobre JSON fijo (`tools/envelope.ts`), system
prompt `UNTRUSTED` (`prompts/system-prompt.ts:20`), registry cerrado (`AI_TOOL_NOT_ALLOWED`),
redactor (P3) y caps de tamaño (P4). La columna "Mitigación" lista lo específico del canal.

| Canal | Tool que lo lleva | Mitigación específica | Test |
|---|---|---|---|
| Nombre de servicio | `list_services`, `get_service`, `get_infrastructure_graph` | Validador de nombre (DNS label) | `adv-inject-service-name` |
| Nombre de proyecto | `get_infrastructure_graph` | `validateProjectName` (texto libre 1-64) | `adv-channel-project-name` (L1) |
| Nombre de environment | `get_infrastructure_graph` | `validateEnvironmentName` | `adv-channel-environment-name` (L1) |
| Nombre de servidor | `list_servers`, `get_server`, `get_infrastructure_graph` | `validateServerName` | `adv-channel-server-name` (L1) |
| Hostname de dominio | `get_infrastructure_graph` (nodo `Domain`) | Hostname LDH normalizado | `adv-inject-domain-hostname` |
| Nombre de env var | `get_logs` (la app los imprime; ningún tool lista env vars) | `openServiceRedactor` sobre valores | `adv-inject-env-var-name` |
| Log de runtime | `get_logs` | `openServiceRedactor`, cap de líneas (≤ 100) y bytes | `adv-inject-runtime-log` |
| Log de build | `get_logs` | Igual que runtime | `adv-channel-build-log` (L1) |
| Mensaje de commit | `get_logs` (build, `HEAD is now at`) | Igual que runtime | `adv-inject-commit-message` |
| Error de deployment | `get_deployment`, `list_deployments` | `error_code` fijo + mensaje con cap | `adv-inject-deployment-error` |
| Metadata de activity | `get_logs` (fuente activity) | Cerrado: `activityEntry` expone solo acción, outcome, error code y `observedState` allowlisted | `channels.test.ts` "activity metadata never reaches the model" |

`channels.test.ts` falla si un canal del modelo no tiene test en `cases.yaml` o en el propio archivo.

## Canary AI (A2)

`tests/integration/activity/canary-ai.test.ts` (Ubuntu 24.04, sshd + dockerd reales) siembra la
SSH key, un secret de aplicación, el token Git HTTPS y la key AI; conecta, despliega, falla un deploy
y hace cinco asks (tres adversariales) por el path real. 31-03 añade una key rechazada por el
provider (el stub la repite en el body), dos fallos del provider a mitad de conversación (401 y 400,
también la repiten) y errores de ruta (404 conversación, 422 pregunta vacía, 422 key vacía). Busca
cada valor, su prefijo y su base64 en requests al provider, ambos SSE, Redis, filas AI y de tools,
activity, loggers, respuestas HTTP y salidas SSH: 0 coincidencias. Forma parte de
`pnpm security:scan-leaks`.
