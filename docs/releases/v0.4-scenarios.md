# Noodara v0.4 — Matriz de escenarios (QA-15, roadmap §9.8 y §9.10)

Cada escenario apunta a un test nombrado. `tests/unit/deploy-engine/scenario-map.test.ts` (datos en
`tests/integration/deploy-engine/scenario-map.ts`) verifica las tres tablas: falla si falta una fila, si el
test no existe o es ambiguo, si está saltado (`.skip`, `.todo`, `.skipIf`, `.runIf`, `.fixme`, `context.skip()`,
`return` según la versión) o si un escenario de integración no corre en las dos versiones de Ubuntu.

## Integración (QA-15)

Corren una vez por versión (`describe.each(DEPLOY_ENGINE_UBUNTU_VERSIONS)`, sshd + dockerd reales). Los tests de
`tests/integration/proxy/` terminan con `expectRemoteMatchesDatabase` (`tests/integration/proxy/remote-state-probe.ts`):
contenedores, redes `noodara-net-*`, archivos de `dynamic/` y estado del proxy en el servidor coinciden con la base.

Comandos:
`NOODARA_TEST_UBUNTU=all pnpm exec vitest run --config vitest.integration.config.ts tests/integration/proxy` y
`NOODARA_TEST_UBUNTU=all pnpm exec vitest run --config vitest.integration.config.ts tests/integration/deploy-engine/runtime-env.test.ts`
