# Noodara v0.4.0 — Domains, Networking, Secrets

## Features

- Traefik proxy per server: one `noodara-traefik` container on ports 80 and 443, installed from
  the server's detail, with its status shown there.
- Domains: point a hostname at a service, follow the DNS instructions, and see DNS and certificate
  status per domain. HTTP redirects to HTTPS by default.
- Automatic HTTPS: certificates from Let's Encrypt (HTTP-01), renewed by the proxy.
- Variables with precedence: set them on a project, an environment or a service; the most specific
  wins (`service > environment > project`). The effective view shows each final value and its
  source.
- Secrets: encrypted at rest, write-only (never returned by the API or shown in logs), referenced
  from variables by name. Applied on the next deploy.
- Integration matrix on Ubuntu 22.04 and 24.04 with real sshd, dockerd and Pebble
  (`v0.4-scenarios.md`).

## Upgrade from v0.3.0

Re-run the install command; it upgrades in place and keeps your `.env` secrets and data.
Migrations `0014`-`0017` (domains, variables, secrets, proxy state and the configure step) run on
boot:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo sh
```

To try the release candidate, pin it without a leading `v`. Release candidates are GitHub
prereleases and are never installed by default:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo NOODARA_VERSION=0.4.0-rc.1 sh
```

After upgrading, install the proxy on each server that should serve domains. Services without a
domain keep working on their published port.

## Downgrade

Pin the previous version; the installer prints it after an upgrade:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo NOODARA_VERSION=0.3.0 sh
```

Back up the database first: migrations 0014+ are not reverted. v0.3.0 cannot read domains,
variables or secrets, so they are not shown or applied, and a redeploy under v0.3.0 starts the
container without them. The data stays intact; upgrading again restores it. The proxy container
keeps running on the server.

## Known limits

- Variable and secret values are single-line.
- Values are visible on the server to anyone with Docker access (`docker inspect`).
- The panel itself is not served through the proxy.
- No DNS-01 challenge, wildcard domains or Cloudflare proxy mode: ports 80 and 443 must be
  reachable for HTTP-01.
- A deploy still swaps containers: the proxy answers `502` for that domain during a short window
  (well under a second measured, under 3 seconds in tests).
- Single worker, one admin account; Ubuntu 22.04 and 24.04 servers only.
