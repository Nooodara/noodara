# Noodara v0.5 — Matriz de escenarios (roadmap §10.1–§10.3 y diagnósticos §10.8)

Cada ítem apunta a un test de integración nombrado que corre una vez por versión
(`describe.each(DEPLOY_ENGINE_UBUNTU_VERSIONS)`, sshd + dockerd reales). `tests/unit/deploy-engine/scenario-map.test.ts`
(datos en `tests/integration/deploy-engine/scenario-map.ts`, `checkV05ScenarioMap`) verifica las cuatro tablas contra el
roadmap y `DIAGNOSES` de `@noodara/domain`: falla si falta una fila, si el test no existe o es ambiguo, si está saltado
(`.skip`, `.todo`, `.skipIf`, `.runIf`, `.fixme`, `context.skip()`, `return` según la versión) o si no corre en las dos
versiones de Ubuntu.

Comando: `NOODARA_TEST_UBUNTU=all pnpm exec vitest run --config vitest.integration.config.ts tests/integration/observability`

Los nodos opcionales de §10.3 (Volume, External dependency) no existen como entidades: el graph no los emite
(`GRAPH_NODE_KINDS`), y el test unitario falla si se agrega un tipo de nodo sin fila aquí.
