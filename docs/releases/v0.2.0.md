# Noodara v0.2.0 — Projects & Services

## Features

- Projects, environments and services: organize work as Project, Environment, Service, each
  environment bound to one of your servers.
- Services from a Git repository (HTTPS token supported, host key pinned on first use), a
  Dockerfile path or a pre-built image.
- Deploy from the panel with live build and runtime logs and the real container state, plus
  cancellation and cleanup of stale and orphaned containers, images and build cache (age-based
  build cache prune, once a day per server).
- Stale `QUEUED` deployments are failed instead of left hanging when enqueue and undo both fail.
- Installer hardening: `.env.bak-*` pruning (newest 5, `NOODARA_ENV_BACKUPS_KEEP`), log rotation
  on all services, smaller images, and the default version never resolves to a release candidate.
- Public site and docs describe the v0.2 flow end to end.

## Upgrade

Re-run the install command; it upgrades in place and keeps your `.env` secrets and data:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sh
```

To try a release candidate, pin it: `NOODARA_VERSION=v0.2.0-rc.1`. Release candidates are GitHub
prereleases and are never installed by default.

## Rollback

Pin the previous version; the installer prints it as the rollback hint after an upgrade:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | NOODARA_VERSION=<previous-version> sh
```

## Known limits

- No domains, TLS or reverse proxy: services are reached on their published port.
- No environment variables or secrets management for applications: put configuration in the image.
- Single worker: deployments run one at a time.
- No webhooks, healthchecks or automatic rollback.
- One admin account; Ubuntu 22.04 and 24.04 servers only.
