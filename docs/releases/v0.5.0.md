# Noodara v0.5.0 — Observability + AI Read-Only

## Features

- Metrics: CPU, memory and disk for each connected server and its service containers, sampled
  over the existing SSH connection (nothing installed on the server), with status pills for high
  disk, high memory, out-of-memory kills and crash loops.
- Logs: one view per service for build, deploy, runtime and activity logs, with time range,
  level, search and follow. Runtime logs stay on the server and are read on demand. Secret values
  are redacted from every line.
- Infrastructure Graph: servers, projects, environments, services, domains and their relations,
  every node linked to its detail page.
- Ask Noodara: questions about your infrastructure answered with your own Anthropic or OpenAI key
  (BYOK), with cited evidence. The assistant is read-only, enforced by the backend.
- Integration matrix on Ubuntu 22.04 and 24.04, a versioned AI eval suite and adversarial tests
  (`v0.5-scenarios.md`).

## New configuration

Both are optional; leave them unset for the defaults.

| Variable | Default | Range |
|---|---|---|
| `NOODARA_METRICS_INTERVAL_MS` | `60000` (1 minute) | 30000-300000 |
| `NOODARA_METRICS_RETENTION_HOURS` | `168` (7 days) | 1-720 |

There is no AI variable: the provider and key are set in the panel.

## Set up the AI assistant (BYOK)

1. Open **Settings**, find **AI assistant**.
2. Pick Anthropic or OpenAI and a model, paste your API key and save. Noodara makes one short
   call to check it; a rejected key is not saved.
3. Select **Ask a question**.

The key is encrypted at rest and only its last 4 characters are shown. Nothing is sent to a
provider until a key is saved. Usage is billed by your provider.

## What is sent to the provider

Per question: a fixed system prompt, the read-only tool definitions, your question and up to 40
recent messages of the conversation, and the results of the tools the model calls (each capped
at 32 KiB, logs at 100 lines). Tool results are redacted first: secret values, private keys and
tokens become `[REDACTED:<type>]`, and secrets appear only as `<secret:name>`. SSH credentials,
host keys, the provider key and your password are never sent.

## Upgrade from v0.4.0

Re-run the install command; it upgrades in place and keeps your `.env` secrets and data.
Migrations `0018` (new enum values) and `0019` (metric samples, container observations, AI
settings, conversations, messages and tool calls) run on boot:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo sh
```

To pin this exact release, write it without a leading `v`:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo NOODARA_VERSION=0.5.0 sh
```

Metrics start on the first interval after boot. The AI assistant stays off until you add a key.

## Downgrade

Pin the previous version; the installer prints it after an upgrade:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo NOODARA_VERSION=0.4.0 sh
```

Back up the database first: migrations 0018+ are not reverted. v0.4.0 does not read the new
tables, so metrics, conversations and the AI settings are not shown and metrics stop being
collected or pruned. The saved AI key stays encrypted in the database. Activity events with the
`ai` actor stay stored. Upgrading again restores everything; samples taken while downgraded are
missing.

## Known limits

- Metrics have no alerts or notifications; thresholds are shown as status only.
- The panel itself is still not served through the Traefik proxy; put your own TLS proxy in
  front of it.
- One AI provider active at a time; a question uses at most 16 tool calls.
- The assistant cannot deploy, restart, change settings, run commands or read secret values.
- Single worker, one admin account; Ubuntu 22.04 and 24.04 servers only.
