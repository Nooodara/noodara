## Hallazgos

1. **Instalador: un pin con `v` rompía el pull** (desde v0.1). `.env` guardaba la versión normalizada, pero Compose interpolaba la variable exportada sin normalizar. Corregido en 14-29 y publicado (`install.sh` se sirve desde `main`); los docs usan pins sin prefijo, válidos para ambos instaladores.
2. **Servidores descubiertos en v0.1 bloquean servicios git**: `docker_buildkit_available` queda `NULL` tras el upgrade y v0.2 lo trata como "no", con `SERVER_BUILDKIT_UNAVAILABLE` ("enable BuildKit") aunque BuildKit esté. Re-ejecutar discovery lo corrige. Falta: distinguir desconocido de falso y pedir discovery.
3. **El workspace de deploy exige root**: `/opt/noodara-deploy` no se puede crear con un usuario SSH no-root (el caso de este host, y el recomendado). Además se clasifica como `CLONE_FAILED` ("check the repository URL… deploy key"), lo que confunde.
4. **Falso positivo de Git LFS**: la detección marca LFS si *cualquier* archivo de texto contiene `version https://git-lfs.github.com/spec/v1`. El repo de Noodara no usa LFS (sin `.gitattributes`, sin punteros) y es rechazado; un puntero real tiene esa cadena como primera línea.
5. Menor: el rollback se anuncia como "Upgraded from 0.2.0-rc.1 to 0.1.0".

Veredicto rc.1: NOT READY por los hallazgos 2–4. Corregidos en 14-29, 14-30 y 14-31; se publicó rc.2.
