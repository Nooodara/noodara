Stable v0.5.2 is published as Latest at the exact independently approved RC commit
`3a34f0daa0a045c48039b2edc882d5ba3bf90fba`; [stable distribution evidence](v0.5.2-gate.md#final-stable-distribution-evidence--2026-11-10)

## Security fix

v0.5.1 can expose an application's secret when the application prints it through the
authenticated legacy runtime endpoints `GET /api/projects/:projectId/services/:serviceId/logs`
(JSON tail) and `GET /api/projects/:projectId/services/:serviceId/logs/follow` (NDJSON follow).
v0.5.2 opens a service-scoped redactor before SSH, using the selected service's visible project,
environment and service secrets. Authorization and project/service ownership checks remain in
place. If the required secrets cannot be loaded or decrypted, the request fails closed before
SSH instead of returning raw output. The lease survives final output flush and session cleanup.

The existing minimum length policy remains: app-secret values of at least 8 characters are
registered, including eligible multiline components; exact, base64 and URL-encoded forms are
redacted. Shorter values are outside this guarantee. Each request takes a snapshot of secrets
visible when it opens. Deleted or rotated historical values are not loaded, changes made after
a follow starts are not added, and a compromised application printing another service's secret
is outside its scope. Docker's original logs are not retrospectively scrubbed. Investigate prior
exposure and rotate affected secrets; this update cannot undo already disclosed output.

The v0.5.1 H2 AI tool-result redaction fix and regressions remain included. AI remains read-only.
The legacy regression covers authenticated HTTP, encrypted PostgreSQL and real SSH/Docker on
Ubuntu 22.04 and 24.04, including both streams, multiline/final partial output, failures,
authorization and cleanup. [Phase 33 evidence](../security/legacy-runtime-log-redaction/README.md)
is historical local proof; [candidate gates](v0.5.2-gate.md) track release validation separately.

## Downgrade

The schema remains compatible with v0.5.1; pin `NOODARA_VERSION=0.5.1` when re-running the
installer to downgrade. Downgrading restores M2: legacy tail/follow can again return secrets
printed by an application. The v0.5.1 H2 AI fix remains in that version. Historical notes and tags
are preserved. No upgrade or downgrade removes raw secrets already retained in Docker logs.
