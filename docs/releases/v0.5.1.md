# Noodara v0.5.1 — AI secret redaction hotfix

## Security fix

v0.5.0 could send an application's secret to the configured AI provider when a connected server
reported that value in discovered text (hostname, operating system, architecture or Docker
versions), or when it appeared in a deployment error. Exploitation through discovery requires
control of a connected server; a failing application can also include its own secret in error
output. The AI must query the affected data for it to reach the provider.

v0.5.1 redacts server, service and deployment tool results using the affected services' secrets
before returning them to the model. If the secrets needed for redaction cannot be opened, the
tool returns `TOOL_UNAVAILABLE` instead of unredacted data. The AI remains read-only.

The regression suite plants a synthetic service secret in discovery fields and deployment
errors, checks global and project scopes, and verifies the failure path. The threat model's
field coverage is derived from the actual tool projections.

## Upgrade from v0.5.0

Upgrade installations using the AI assistant. Re-run the installer to upgrade in place:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sudo NOODARA_VERSION=0.5.1 sh
```

There are no new migrations or configuration variables. Existing data, services and encrypted
BYOK settings are preserved. A release candidate must be pinned explicitly as `0.5.1-rc.1`;
prereleases are not installed by default.

This update prevents future exposure through these channels. It cannot remove information
already sent to a provider. If a connected host was compromised or a deployment error contained
a secret while the AI queried it, investigate that exposure and rotate the affected secret.

## Downgrade

The database remains compatible with v0.5.0, but downgrading restores this security gap.
The v0.5.0 tag is preserved. Other v0.5.0 limitations remain unchanged.
