# Noodara v0.3.0 — Reliable Deployment Engine

## Features

- Healthchecks: a new container must pass its check before the deployment is `SUCCESS`; timeouts
  and wrong statuses fail the attempt with a clear code.
- Rollback: a failed healthcheck restores the previous container automatically, and you can roll
  back to the previous version on demand. Retained images are kept so the rollback target exists.
- GitHub webhooks: a signed push webhook deploys the pushed commit.
- Idempotency: the same push delivered twice (or concurrently) deploys once.
- Cancel and crash recovery: cancelling a deployment cleans up after it, and a worker that dies
  mid-deploy is recovered on retry without orphan containers.
- Integration matrix on Ubuntu 22.04 and 24.04 with real sshd and dockerd (`v0.3-scenarios.md`).

## Upgrade

Re-run the install command; it upgrades in place and keeps your `.env` secrets and data. Migrations
`0011`-`0013` (new deployment states, one-active-deployment index, deployment columns and the
`webhook_deliveries` table) run on boot:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | sh
```

To try the release candidate, pin it without a leading `v`: `NOODARA_VERSION=0.3.0-rc.1`. Release
candidates are GitHub prereleases and are never installed by default.

## Rollback

Pin the previous version (for example `NOODARA_VERSION=0.2.0`); the installer prints it after an
upgrade:

```sh
curl -fsSL https://raw.githubusercontent.com/nooodara/noodara/main/install.sh | NOODARA_VERSION=<previous-version> sh
```

Back up the database before downgrading: migrations 0011-0013 are not reverted.

## Known limits

- No domains, TLS or reverse proxy: services are reached on their published port.
- No environment variables or secrets management for applications yet.
- Single worker: deployments run one at a time.
- One admin account; Ubuntu 22.04 and 24.04 servers only.
