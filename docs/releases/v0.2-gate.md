## Política de build cache (D12, ADR 0009)

Tras un deployment `SUCCESS` el worker corre `docker builder prune --force --filter until=168h` (sin `--all`), máximo una
vez por servidor cada 24 h (`SET NX EX 86400`), nunca con otro deployment `BUILDING`, timeout de 120 s; un fallo libera la
clave y no afecta al deployment. `NOODARA_BUILD_CACHE_PRUNE=off` lo desactiva. Tests: `build-cache-prune.test.ts` y
`runtime-pipeline` 14-10 A3.

## Commit publicado ↔ commit local

El repo público se publica con subtree split + rebase, así que los SHA difieren. `d828db4` (tag `v0.2.0`/`v0.2.0-rc.2`) tiene el árbol `c739f62facb31957a0caf1317d86a90f83acb2cf`, idéntico a `noodara/code` en el commit local `4eab389`. Se comprueba con `git rev-parse 4eab389:noodara/code` en el monorepo y `git rev-parse d828db4^{tree}` en el repo público.
