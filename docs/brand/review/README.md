# Brand review captures

Working artifacts for the brand approval gate (BRAND-03, decision D-14): every logo concept shown
both on a static brand board and mounted in the real Noodara app, in light and dark.

Everything in this directory **except this file** is ignored by git. The captures are output, not
source: they are regenerated by one command whenever the geometry or the design tokens change, and
only the concept the user approves is ever committed — the approval plan copies that concept's
files into `docs/brand/approved/`.

## What gets produced

For each concept `a`, `b`, `c` and each theme `light`, `dark`:

| File | What it shows |
| --- | --- |
| `<concept>/board-<theme>.png` | The brand board: the three lockups, the construction sheet on the 24-unit grid, the 16/32/64/256 scale ladder, the favicon tile on two simulated tab strips, and the Open Graph preview |
| `<concept>/login-<theme>.png` | `/login`, unauthenticated, with the lockup above the card heading |
| `<concept>/setup-<theme>.png` | `/setup`, unauthenticated, same placement |
| `<concept>/sidebar-expanded-<theme>.png` | `/servers` at 1440×900, lockup at the top of the sidebar |
| `<concept>/sidebar-rail-<theme>.png` | `/servers` at 1024×800, monogram at the top of the 64 px icon rail |
| `<concept>/sidebar-*-<theme>-crop.png` | The same sidebar, cropped tight, for judging the mark at its real size |

## Regenerating

The boards need nothing but Node:

```sh
pnpm brand:boards
```

The in-app captures boot the real stack (Postgres, Redis, the API, the worker and the built web
app), so they need Docker running and a prior build:

```sh
pnpm build
pnpm brand:review
```

Restrict either command to one concept while iterating:

```sh
pnpm brand:boards -- --concept b
pnpm brand:review -- --concept b
```

### Against a dev server instead of Docker

If you already have `pnpm dev` running against your own Postgres/Redis, point the capture script at
it instead of booting a second stack. All three variables are required — the script has no default
URL and no default account:

```sh
BRAND_REVIEW_BASE_URL=http://localhost:3000 \
BRAND_REVIEW_EMAIL=you@example.test \
BRAND_REVIEW_PASSWORD=... \
pnpm brand:review
```

## What the script cannot do

It cannot screenshot the **favicon in the browser tab**. Playwright captures page content, never
the browser's own chrome. The board shows the tile on a *simulated* tab strip, labelled as such;
the real tab is a manual check — open the app in your own browser and look at it before approving.

## Reviewing

Until the approved concept is mounted for real (a later plan), the mark is put on screen by
inserting the rendered SVG into the live DOM at capture time. That markup is the exact output of
the components the app will mount, and it inherits the real theme tokens, but nothing in
`apps/web/` or `packages/ui/` is modified to produce these images.
