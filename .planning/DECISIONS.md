- 2026-10-30: Reverse proxy = one Traefik container per user server (`noodara-traefik`, image pinned by digest, binds host 80/443), managed over SSH like any other deploy resource. Configuration by the **file provider** under `/opt/noodara-proxy/` (static config + one dynamic file per service, written atomically temp + rename), never the Docker provider: no `docker.sock` mount into Traefik, and domain changes apply without recreating the service container. Traefik is connected to each routed service's `noodara-net-<serviceId>` and routes to `http://noodara-<serviceId>:<internalPort>` by Docker DNS; ADR 0011 (21-01) must prove the name follows the `-prev` swap. The panel itself is NOT routed through Traefik in v0.4 (`NOODARA_PUBLIC_URL`/`NOODARA_PORT` unchanged); `NOODARA_PORT` on 80/443 collides with the proxy and the preflight says so (`PROXY_PORT_IN_USE`). No installer change in v0.4.
- 2026-10-30: Replacement stays stop-then-start (decision #14); Traefik answers 502/503 during the swap window, documented. Zero-downtime switchovers are not a v0.4 criterion and are not planned.
- 2026-10-30: TLS = Traefik's built-in ACME, HTTP-01 only, `acme.json` (0600) stays on the server; the control plane never reads it (it holds private keys). Certificate status is derived with a host-side TLS handshake probe (`openssl s_client` to 127.0.0.1:443 with SNI, output limited to issuer and notAfter; openssl availability on stock Ubuntu is measured in 21-01) on a bounded cycle (`NOODARA_CERT_CHECK_INTERVAL_MS`, default 10 min) plus a short-backoff check after every domain change. CA URL configurable (`NOODARA_ACME_CA_URL`, default Let's Encrypt production; Pebble in tests via `NOODARA_ACME_CA_ROOT_FILE` test seam); ACME account email = admin email unless overridden per server. No DNS-01, no wildcards, no custom certificate upload, no Cloudflare integration in v0.4.
- 2026-10-30: HTTP → HTTPS redirect is a per-domain flag (`https_redirect`, default on) rendered unconditionally into the dynamic config, independent of certificate status: the config is a pure deterministic function of the domain rows (needed for QA-17), and while a certificate is PENDING the browser sees Traefik's default certificate for seconds, not a broken redirect loop.
- 2026-10-30: Proxy lifecycle is implicit: adding the first domain on a server enqueues `proxy-install-<serverId>` (bounded job, states `NOT_INSTALLED | INSTALLING | RUNNING | FAILED` on `servers`); removing the proxy is explicit and only allowed with zero domains on that server (`PROXY_IN_USE`). Deleting a server (no services) removes the proxy best-effort without blocking the deletion. Deleting a service removes its dynamic file and disconnects Traefik from `noodara-net-<serviceId>` before the network is removed (otherwise `docker network rm` fails).
- 2026-10-30: DNS validation is advisory: the control plane resolves the hostname (Node resolver through the existing `DnsResolverLike` seam, 3 s timeout) and compares it with the server's IPs (`Server.host` resolved, or itself when an IP); outcomes `RESOLVES | MISMATCH | UNRESOLVED | UNAVAILABLE`. A domain can be added before DNS points at the server; `CERT_DNS_MISMATCH` becomes the failure cause when issuance exceeds `NOODARA_CERT_ISSUE_TIMEOUT_MS` (default 10 min) and DNS is not RESOLVES.
- 2026-10-30: Env vars and secrets are runtime-only in v0.4 and injected with `docker create --env-file <workspace>/secrets/env` (0600, outside the build context, removed with the workspace). Consequences accepted and documented: values are single-line (`ENV_VALUE_MULTILINE`, hint: base64-encode), `--env-file` semantics are literal (measured in 21-01), and resolved values are visible in the container's environment on the user's own server (`docker inspect` by anyone with Docker access), as in every comparable PaaS. Noodara's own `docker inspect`/`docker ps` formats never select `.Config.Env`. Build args are out of v0.4 (not a §9 criterion; they land in `docker history`).
- 2026-10-30: Secrets live in their own `secrets` table (scope `project | environment | service`, name `^[a-z][a-z0-9_]{0,63}$`), encrypted with the existing envelope and `key_version`, covered by `noodara secrets rotate`, `SecretKind` gains `app_secret`. A variable references a secret as `<secret:name>` resolved by the same `service > environment > project` precedence at deploy time. Runtime config snapshot v2 stores plain values and `{secretRef, secretVersion}` (never secret values); rollback restores plain values from the snapshot and resolves references at rollback time; a missing secret fails the attempt with `SECRET_UNRESOLVED` before any container change. Redacted view = `••••••••` plus the last 4 characters only when the value has ≥16 characters.
