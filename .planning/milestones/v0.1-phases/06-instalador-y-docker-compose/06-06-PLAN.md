<objective>
Resolve the three values the installer cannot know in advance: which release to install (D-04),
what public URL the panel will be reachable at (D-07), and which image registry/tag prefix to pull
from — including the undocumented test-only override (D-19) that makes the Docker-in-Docker suite
possible without a registry.

Purpose: on a NAT-ed VPS the local IP is private, so a wrong `NOODARA_PUBLIC_URL` makes every
mutating request fail with `FORBIDDEN_ORIGIN` from the phase-4 Origin guard — the resolution order
in D-07 exists precisely to avoid that. And D-04's "exact tag, never `:latest`" is what stops a
container restart from silently changing version.
Output: five resolution functions in `install.sh`, fully unit-tested against local stubs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party IP-echo services → install.sh | an untrusted remote body becomes part of `NOODARA_PUBLIC_URL`, which the Origin guard compares against |
| GitHub release metadata → install.sh | an untrusted remote value becomes the image tag the installer pulls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-29 | Tampering | an IP-echo service returning HTML, an injected string, or a hostile address that lands in `NOODARA_PUBLIC_URL` | mitigate | The response is shape-validated as a plain IPv4 address with a `case` pattern before use; anything else advances to the next service in the chain. The value is only ever written to `.env` and compared for equality by the Origin guard — it never reaches a shell command. |
| T-06-30 | Tampering | the release tag from a redirect/JSON body reaching a `docker pull` argument | mitigate | The tag from every source (operator `NOODARA_VERSION`, redirect tail, API body) is normalised once and then unconditionally validated by `noodara_validate_tag` (first char `[A-Za-z0-9_]`, rest `[A-Za-z0-9_.-]`, max 128) before being printed or written to `.env`; newline, space, `=`, `;`, `/`, `$`, backtick and quotes exit 40 — Task 1 behavior and acceptance criteria (ASVS V5). |
| T-06-07 | Tampering | mutable image references letting a restart silently change version | mitigate | D-04: the exact resolved tag is written to `.env` and the Compose file references `${NOODARA_VERSION}`; `:latest` appears nowhere. Enforced by an acceptance grep in Plan 06-07. |
| T-06-31 | Denial of Service | a hanging IP-echo service blocking the install indefinitely | mitigate | Every call goes through `noodara_fetch_url`'s `--connect-timeout $NOODARA_FETCH_TIMEOUT --max-time 15`; there is no other `curl` call site, asserted by a grep-count criterion. |
| T-06-32 | Spoofing | `NOODARA_INTERNAL_IMAGE_PREFIX` (D-19) being discovered and used to point a real install at an attacker's registry | accept | The override requires local shell access to set an environment variable for the install command, which already implies root on the target host — an attacker with that access does not need this override. It is deliberately undocumented (D-19) and never mentioned in `docs/install.md`. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No new package. `curl`, `awk`, `sed` and `ip` are preflight-checked base commands (Plan 06-02). |
</threat_model>
