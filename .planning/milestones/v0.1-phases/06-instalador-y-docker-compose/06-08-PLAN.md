<objective>
Implement D-14: install Docker Engine and the Compose v2 plugin from Docker's official apt
repository, one named step at a time, only when they are missing.

Purpose: Coolify's documented "fails silently on step Docker" is the negative example here. The
exact apt sequence is already proven in this repo — `tests/integration/images/sshd-ubuntu-22.04/Dockerfile`
runs it in CI on every integration run — so this task translates a known-good sequence into POSIX
`sh` rather than inventing one, and wraps each step in its own error message.
Output: the Docker installation functions in `install.sh` plus a stub-driven unit suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| download.docker.com → VPS apt | a third-party repository is added to the host's trusted package sources as root |
| install.sh → host package manager | the installer permanently modifies the system's software sources |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Spoofing | an unsigned or wrong-origin apt repository serving a trojaned docker-ce | mitigate | Docker's own GPG key is fetched over TLS from `download.docker.com` and the sources line is written with `signed-by=/etc/apt/keyrings/docker.asc`, so apt refuses any package not signed by that exact key. No `[trusted=yes]`, no `apt-key add`, no mirror fallback. This is the identical sequence `tests/integration/images/sshd-ubuntu-22.04/Dockerfile` already runs in CI. |
| T-06-37 | Tampering | executing a third-party installer script as root (`get.docker.com`) | mitigate | D-14 bans it; asserted by a `grep -c 'get.docker.com'` of 0. CONTEXT.md names "an installer that does not run third-party scripts as root" as an explicit trust differentiator versus Coolify/Dokploy. |
| T-06-38 | Denial of Service | an interactive apt prompt hanging an unattended `curl \| sh` forever | mitigate | Every apt invocation uses `-y` and `DEBIAN_FRONTEND=noninteractive`; asserted by test and by grep. |
| T-06-39 | Tampering | a re-run reinstalling or restarting Docker and killing the running stack | mitigate | `noodara_ensure_docker` performs zero package operations when both Docker and the Compose plugin are present; asserted by a zero-invocation test. INST-02's "no-op when nothing to do" depends on this. |
| T-06-40 | Repudiation | a failed install reporting a generic message so the operator cannot tell which step broke | mitigate | One function per step, one `noodara_fail docker-install-failed "<step name>: …"` per step; step attribution asserted for at least three steps. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No npm package. The apt artifacts (`docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`) are already recorded as Approved in 06-RESEARCH.md's Package Legitimacy Audit, first-party vendor repo, GPG-signed. |
</threat_model>
