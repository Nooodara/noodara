<objective>
Implement INST-03: the complete preflight. Every check is a separate, injectable `sh` function
with its own exit code and message, and `noodara_preflight` runs them in one documented order,
stopping at the first failure.

Purpose: Coolify's own still-open port-8000 silent-failure (06-RESEARCH.md Pattern 4, PITFALLS #5)
is exactly the class of defect D-17 exists to prevent. A preflight that reports the wrong root
cause, or reports several at once, is as unhelpful as no preflight.
Output: `noodara_preflight` plus eight predicates in `install.sh`, fully unit-tested under real
`sh`/`dash` with no system mutation and no network.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env vars → install.sh | `NOODARA_PORT`, `NOODARA_SKIP_RESOURCE_CHECK` and the undocumented test overrides are operator-controlled input |
| host system state → install.sh | `/etc/os-release`, `/proc/meminfo`, `ss`, `df`, `snap` outputs are attacker-influenceable on a compromised host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-14 | Tampering | `NOODARA_PORT` flowing into a compose `ports:` mapping | mitigate | `noodara_resolve_port` validates digits-only and the 1–65535 range with a `case` pattern before the value is ever written to `.env` or used in a command, so no shell metacharacter can reach a later `docker compose` invocation (ASVS V5). |
| T-06-15 | Elevation of Privilege | preflight running as a non-root user and half-completing | mitigate | `noodara_check_root` is the first check in the order and exits 10 immediately; nothing is written before the whole preflight passes, asserted by the empty-tmpdir test in Task 3. |
| T-06-16 | Denial of Service | a preflight that continues past the first failure and reports the wrong cause | accept-with-control | Fail-fast ordering is enforced by `set -e` plus `noodara_fail`'s immediate exit, and the combined-failure tests pin the reported cause. Residual risk (an ordering that is deterministic but still not the most useful cause for some exotic host) is accepted for v0.1 and re-examined by the layer-2 scenario matrix in Plan 06-12. |
| T-06-17 | Information Disclosure | preflight output echoing host details | mitigate | Messages name only the detected OS id/version, architecture, RAM/disk figures and port number — never file contents, environment dumps or command output (noodara-security §8). |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No package is installed by this plan. 06-RESEARCH.md's Package Legitimacy Audit records zero npm additions for this phase. |
</threat_model>
