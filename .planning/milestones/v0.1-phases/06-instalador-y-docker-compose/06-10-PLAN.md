<objective>
Build the Docker-in-Docker test fixture D-18's layer 2 requires: a privileged Ubuntu 22.04 and
24.04 container, each running its own `dockerd`, into which the real `install.sh` and the locally
built Noodara images can be injected and executed.

genuine Ubuntu dash. Getting the fixture right — and proving it works on its own — before writing
four scenario files is what keeps those files about scenarios rather than about plumbing.
Output: two fixture images sharing a common entrypoint, a Testcontainers helper, and a harness
self-test.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test host Docker daemon → privileged fixture container | a privileged container can escape to the host; it exists only inside the test suite |
| host image store → nested daemon | locally built images are transferred as a tar, with no registry and no signature |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-47 | Elevation of Privilege | `withPrivilegedMode(true)` on the fixture container | accept | A nested `dockerd` requires it and there is no meaningful alternative for testing a host installer. The exposure is bounded: the fixture image is project-owned and built from a Dockerfile in this repo, it is only started by this repo's own test suite, it runs no untrusted input, and it is always stopped by the idempotent `stop()` plus the `noodara.test=true` stray-container gate. Documented rather than silently inherited. |
| T-06-48 | Tampering | a stray privileged container surviving a crashed run and remaining on a developer's machine | mitigate | `noodara.test=true` label on every container, `assertNoStrayTestContainers()` in `afterEach`, and the existing per-job "Fail if any noodara.test container survived" step in `ci.yml`/`nightly.yml` already covers whichever job runs this suite. |
| T-06-49 | Spoofing | the fixture silently running bash as `/bin/sh` and hiding a bashism | mitigate | An explicit first-class test asserts `${BASH_VERSION:-nobash}` prints `nobash` inside both fixtures; without it the whole layer-2 suite could pass while the real `curl \| sh` path stays unproven. |
| T-06-50 | Tampering | the fixture reaching the public internet for Noodara's own artifacts and testing something other than the local build | mitigate | `loadLocalImages` + `NOODARA_INTERNAL_IMAGE_PREFIX` (D-19) means `install.sh`'s pull step is skipped entirely; the scenarios run against images built from this working tree. The fixture image build itself does reach `download.docker.com` and `archive.ubuntu.com`, which is inherent to building an Ubuntu+Docker fixture and matches the existing sshd fixtures' behaviour. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No new npm package; `testcontainers@12.1.0` is already root-pinned. The apt packages installed into the fixture are the same first-party Docker repo artifacts already approved in 06-RESEARCH.md's audit. |
</threat_model>
