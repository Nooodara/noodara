<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| previous installation state → re-run | an existing `/opt/noodara/.env` and two populated volumes are the most valuable thing on the host |
| apt repositories → fixture | the no-Docker scenario installs real packages from the network inside a privileged container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-11 | Tampering | a re-run regenerating secrets and orphaning every encrypted SSH credential | mitigate | Byte-identical `.env` comparison across two real runs, plus a record written between the runs and read back afterwards. This is the strongest available proof short of the real-VPS run in Plan 06-15. |
| T-06-44 | Denial of Service / data loss | a failed upgrade destroying data while "recovering" | mitigate | The broken-version scenario captures `.env` and `docker volume ls` before and after and asserts both unchanged; combined with the unit-level assertion that no `down`/`volume rm` is ever issued. |
| T-06-16 | Denial of Service | preflight reporting a misleading root cause on a multi-failure host | mitigate | The combined snap + busy-port case asserts exit 17 and asserts the port is NOT mentioned — 06-RESEARCH Pitfall 6's explicit requirement. |
| T-06-53 | Information Disclosure | a diff-on-failure assertion dumping `.env` values into CI output | mitigate | The byte-identical assertion reports differing variable NAMES only; values are never printed. |
| T-06-06 | Spoofing | the real apt path installing an unsigned docker-ce | mitigate | The no-Docker scenario exercises the genuine `signed-by=/etc/apt/keyrings/docker.asc` sequence end to end; a wrong key or missing signature makes apt fail and the test fail with it. This is the only place that sequence runs for real before a user's VPS does. |
| T-06-48 | Tampering | privileged fixtures surviving a failed run | mitigate | Idempotent `stop()` in `finally`, `assertNoStrayTestContainers()` in `afterEach`, CI stray-container step. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No new npm package. The apt artifacts installed by the no-Docker scenario are the approved first-party Docker repo packages. |
</threat_model>
