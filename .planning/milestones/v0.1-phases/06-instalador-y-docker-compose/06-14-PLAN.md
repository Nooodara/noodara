  <action>
    Write `docs/install.md` in English with these sections:

    **Requirements** — Ubuntu 22.04 or 24.04, amd64 or arm64, root or sudo, 2 GB RAM recommended
    (1 GB minimum, below which the installer refuses), 5 GB free disk, and a host port available
    for the panel.

    **Install** — the `curl -fsSL <raw URL> | sh` one-liner. Leave the owner/repo placeholder the
    script itself uses and state explicitly that it is filled in when the repository is published
    (D-02/D-03); do not invent a URL.

    **Install without piping to a shell** — the download-read-run alternative: download the script,
    read it, then run it. Mirror the guidance `get.docker.com` itself gives. This is a security
    control, not a footnote: name it as the recommended path for anyone who will not run a remote
    script as root sight-unseen.

    **What gets installed** — the six Compose services, the two named volumes, `/opt/noodara` with
    its mode-600 `.env`, and the single published port. State plainly that Postgres and Redis are
    not reachable from outside the host.

    **First login** — the panel URL and the one-time setup token the installer prints, and the
    pre-seed alternative using `NOODARA_ADMIN_EMAIL` and `NOODARA_ADMIN_PASSWORD`. Note that both
    variables must be set or neither, that the password must satisfy the password policy, and that
    an operator may remove both from `.env` once the admin exists.

    **Plain HTTP warning** — a section of its own, not a note in passing. The default install
    serves the panel over unencrypted HTTP; the installer writes
    `NOODARA_COOKIE_INSECURE=true` in that case, which disables the `Secure` cookie attribute;
    anyone on the path can read the session cookie; HTTPS and automatic certificates arrive in
    v0.4; until then an operator who wants TLS should put a reverse proxy in front, set
    `NOODARA_PUBLIC_URL` to the `https://` origin, and remove `NOODARA_COOKIE_INSECURE`.

    **Firewall** — the `ufw allow <port>/tcp` command, and the precise reality: Docker publishes
    container ports by inserting its own iptables rules, which typically bypass ufw's rules for
    published ports, so a port Docker publishes may be reachable from the internet even when ufw
    shows it as denied. State that the installer never modifies firewall rules, and remind the
    operator about the cloud provider's own firewall. Quote the installer's own message so the two
    cannot drift.

    **Supported variables** — a table of name, default, and effect, covering exactly the operator-
    facing variables: `NOODARA_VERSION`, `NOODARA_PORT`, `NOODARA_PUBLIC_URL`,
    `NOODARA_ADMIN_EMAIL`, `NOODARA_ADMIN_PASSWORD`, `NOODARA_SKIP_RESOURCE_CHECK`, plus the
    post-install `.env` tuning knobs an operator may edit. Do NOT document
    `NOODARA_INTERNAL_IMAGE_PREFIX`, `NOODARA_INSTALL_DIR`, `NOODARA_OS_RELEASE_FILE` or
    `NOODARA_MEMINFO_FILE` — those are test-only (D-19) and documenting them would turn a test seam
    into a supported feature.

    **Upgrade** — re-run the installer (D-09). Secrets and volumes are preserved; only the version
    line changes. Pin a specific version with `NOODARA_VERSION`.

    **Rollback** — re-run with `NOODARA_VERSION` set to the value the installer recorded in
    `NOODARA_PREVIOUS_VERSION`. State clearly that there is no automatic rollback in v0.1 and that
    a failed upgrade leaves data and secrets untouched.

    **Troubleshooting** — a table of the installer's exit codes with their meaning and the
    remedy, taken verbatim from the exit-code table in `install.sh`; how to read logs
    (`docker compose -f /opt/noodara/docker-compose.yml logs <service>`); how to check health
    (`docker compose ps` and the `/health` endpoint); and how to run the operator CLI
    (`docker compose exec api node dist/cli/index.js admin reset` and the `secrets rotate`
    equivalent — verify the exact invocation against the built image before writing it down).

    **Backups** — one honest paragraph: v0.1 has no managed backups; `NOODARA_MASTER_KEY` in
    `/opt/noodara/.env` is unrecoverable if lost and every stored SSH credential becomes
    undecryptable without it; back up that file.
