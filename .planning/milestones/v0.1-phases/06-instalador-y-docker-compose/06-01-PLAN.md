  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → VPS shell | `curl … \| sh` streams remote text straight into a root shell |
| repo → CI | a bashism that only fails on a real user's Ubuntu box, never on the macOS dev machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `curl \| sh` transport | mitigate | All logic lives in function bodies; the only side-effecting top-level statement is the final guarded dispatch, so a truncated stream defines functions and exits without installing. Enforced by `scripts/check-posix-sh.mjs`'s `toplevel-side-effect` + `missing-guard` rules (Task 1), not by review. |
| T-06-02 | Information Disclosure | installer output helpers | mitigate | `noodara_step`/`noodara_warn`/`noodara_note`/`noodara_fail` take a literal message only; no helper interpolates a generated secret. Later plans reuse these four and nothing else for operator-visible output (noodara-security §8). |
| T-06-13 | Denial of Service | shell dialect drift | mitigate | `pnpm check:posix-sh` plus `describe.each(posixInterpreters())` means a bashism fails a named test, and CI (where `/bin/sh` is dash) additionally asserts a dash-family interpreter was actually exercised. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No new package is installed by this plan or this phase (06-RESEARCH.md §"Package Legitimacy Audit": zero npm additions). `bats-core` is explicitly rejected. If any task finds itself reaching for a new dependency, stop and escalate — it would require `scripts/check-package-provenance.mjs` plus an ADR-0000 addendum and a blocking human checkpoint. |
</threat_model>
