<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → `PATCH /api/servers/:id` | Attacker-influenced host/port/user values change a server's identity while a fingerprint captured against the old identity is still stored |
| stored `pendingFingerprint` → `trustFingerprint` | A value captured from one host is promoted as the trusted key of another |
| session store → request guard / SSE heartbeat | An unbounded await on session resolution decides whether a revoked session keeps privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-01 (UF-01) | Spoofing | `services/edit-server.ts` | mitigate | Clear `pendingFingerprint`/`pendingFingerprintSeenAt` on any identity-changing edit while `ERROR`; regression test asserts a following `trustFingerprint` returns `NO_PENDING_FINGERPRINT` |
| T-5-02 (T-4-02) | Elevation of Privilege | `auth/require-session.ts`, `routes/events.ts` | mitigate | `withSessionLookupTimeout` bounds both `getSession` awaits at `SESSION_LOOKUP_TIMEOUT_MS`; a timeout is treated as "no session" |
| T-5-03 | Information Disclosure | timeout error message | mitigate | Fixed literal message with no request-derived interpolation; existing opaque 500 `INTERNAL_ERROR` body unchanged |
| T-5-04 | Denial of Service | SSE heartbeat | accept | A slow session store still costs one bounded await per heartbeat per stream; `NOODARA_SSE_MAX_CONNECTIONS` already caps concurrency |
| T-5-SC | Tampering | npm installs | mitigate | This plan installs no packages; the supply-chain gate is Plan 05-03 |
</threat_model>
