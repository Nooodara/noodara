  <files>apps/control-plane/src/queue/worker-shutdown.ts, apps/control-plane/src/queue/worker-shutdown.test.ts</files>
  <read_first>
    - apps/control-plane/src/worker.ts (the existing `shutdown()` closure — every cleanup step and their exact order must be preserved: `stopHeartbeat`, `queue.close`, `workerConnection.disconnect`, `queueConnection.disconnect`, `publisherConnection.disconnect`, then exit)
    - apps/control-plane/src/events/sse-broadcaster.ts (its `closeAll()` bounds `unsubscribe()` and uses `.catch(() => undefined)` — the precedent for "one cleanup step's failure must never block a later one")
    - apps/control-plane/src/routes/health.ts (the `Promise.race`-against-a-timer shape already used for bounded waits)
    - .planning/phases/05-ui-web/05-PATTERNS.md (section "worker.ts (T-4-32 shutdown try/catch)")
    - .claude/skills/noodara-tdd/SKILL.md (structural-interface / injected-dependency test style used across this repo)
  </read_first>
  <behavior>
    - With a `close` that resolves, every cleanup step runs exactly once, in order, and the injected `exit` is called with 0.
    - With a `close` that rejects, every cleanup step still runs and `exit(0)` is still called.
    - With a `close` that never settles, the sequence proceeds after the injected grace bound elapses (fake timers), and every cleanup step still runs.
    - With a `queue.close` that rejects, the three `disconnect` calls still run and `exit(0)` is still called.
    - Calling the returned shutdown twice runs the sequence only once (the existing `shuttingDown` guard's behaviour).
  </behavior>
  <action>
    Create `apps/control-plane/src/queue/worker-shutdown.ts` exporting `runWorkerShutdown(deps)`, where `deps` is a narrow structural interface — not BullMQ or ioredis concrete types — carrying: `close: () => Promise<void>`, `graceMs: number`, `stopHeartbeat: () => void`, `closeQueue: () => Promise<void>`, `disconnect: readonly (() => void)[]`, `logger: { warn: (obj: unknown, msg: string) => void }`, and `exit: (code: number) => void`. Implement it as: a `Promise.race` of `close()` against a `setTimeout`-resolving grace promise, wrapped in try/catch that logs a warning with `{ err }` (safe after Task 1) and never rethrows; then a `finally`-equivalent cleanup phase that calls `stopHeartbeat()`, awaits `closeQueue()`, and calls every `disconnect` entry — each individually guarded so one throwing or rejecting step never skips the rest (the `sse-broadcaster.ts` `closeAll()` precedent) — and finally `exit(0)`. Keep a module-local re-entry guard so a second invocation is a no-op. Never call `process.exit` directly inside this module; the injected `exit` is what makes it testable.

    Write `worker-shutdown.test.ts` first, using Vitest fake timers for the never-settling case and plain spies for the rest.
  </action>
