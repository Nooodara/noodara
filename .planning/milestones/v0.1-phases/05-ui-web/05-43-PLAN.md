<objective>
Close the WR-A-04 residual named in 05-VERIFICATION.md's `gaps_remaining`: the one call site found (`server.ts`) was fixed, but nothing prevents a future `logger.error(err)` from reintroducing the leak. `logger.ts` has a global `serializers.err` that reduces an error to `{ name }` — but that serializer only protects an error passed UNDER the `err` key.

This was verified empirically while planning, against this repository's own pino 10.3.1 and the exact `serializers.err` config in `logger.ts`: `logger.error(new Error('sk-live-LEAKED-SECRET-VALUE'))` emits `{"err":{"name":"Error"},"msg":"sk-live-LEAKED-SECRET-VALUE"}`. The serializer strips the error object, and pino then copies `err.message` into `msg`. Today there are zero violating call sites; the leak is one careless line away, on the exact paths (SSH failures, Postgres errors, credential decode) whose error messages can carry connection strings.

Output: a `hooks.logMethod` interceptor in `createLogger` that rewrites a leading `Error` argument into `{ err }` plus a message that is never derived from the error, and a regression test that fails if that guard is ever removed.
</objective>

`apps/control-plane/src/logger.test.ts` already has two describes: "createLogger redaction" (2 cases) and "createLogger err serialization (T-4-10, T-4-38)" (4 cases), all using `writableForTests()` and asserting against the REAL emitted JSON via `records()`. Follow that style exactly — assert on emitted output, never on the options object's shape.

pino is 10.3.1. `hooks.logMethod(args, method, level)` is called with the raw argument array for every log call; the hook must invoke `method.apply(this, newArgs)` and must not return a value that pino interprets as a log record.

Why a hook rather than an ESLint rule: a lint rule cannot know whether an identifier passed as the first argument is an `Error` at runtime (`catch (err: unknown)` is the normal shape in this codebase), so it would be both incomplete and noisy. The hook is total, applies to every level, and needs no per-call-site discipline. If you also want a lint rule, it is explicitly out of scope for this plan — do not add one.

Do NOT change `serializers.err` or `REDACT_PATHS`. The existing four err-serialization tests must keep passing unmodified.
