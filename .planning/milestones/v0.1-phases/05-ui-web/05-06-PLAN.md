<objective>
Create `packages/ui` and the component-test harness the whole phase depends on: the package scaffold and monorepo wiring, a working Vitest + jsdom + Testing Library setup, and the token layer.

Purpose: UI-01 requires the shell and every screen to draw exclusively from the locked `noodara-ux-apple` token set, and CLAUDE.md §2.1 requires every component to be written test-first. Both have to be true from the first component onward, which means the token file and the DOM test harness must exist before any component does.
Output: a building, lint-clean, boundary-tagged `@noodara/ui` with `tokens.css`, a Tailwind v4 `@theme` binding, a proven `renderUi` test harness, and ADR-0005 recording the verification strategy.

**Verification strategy (this is what ADR-0005 records):** component behaviour — variants, disabled/loading/active states, aria attributes, callback invocation, the three empty/loading/error states, and "never colour-only" text presence — is verified by **colocated Vitest component tests written before the component** (`X.test.tsx` next to `X.tsx`, per the `noodara-tdd` skill §3). Playwright verifies what jsdom genuinely cannot: cross-screen flows, real-browser keyboard navigation and focus order, theming and computed styles, and the credential-leak surfaces. An earlier draft of this plan declined the DOM stack to avoid four dependencies; that traded away CLAUDE.md §2.1, which is non-negotiable, so the five packages go through the existing provenance gate and the existing blocking human checkpoint in Plan 05-03 instead.
</objective>
