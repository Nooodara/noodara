## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → repo | Third-party package code executes at install and at runtime inside the control plane |
| operator env → process | Operator-supplied tuning values reach queue concurrency and socket limits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-SC | Tampering | `pnpm add bullmq/ioredis/@testcontainers/redis` | mitigate | Extend `scripts/check-package-provenance.mjs` with exact `owner/repo` equality for all three and require exit 0 before install; record verdict in ADR 0000. All three are `[OK]` per RESEARCH's slopcheck audit, so no `[ASSUMED]`/`[SUS]` human checkpoint is required; `concurrently` (`[ASSUMED]`) is deliberately not installed |
| T-4-06 | Denial of Service | SSE connection accounting | mitigate | `NOODARA_SSE_MAX_CONNECTIONS` validated here with range 1–1000 so an unbounded or zero value can never reach the runtime; enforcement lands in Plan 04-09 |
| T-4-13 | Denial of Service | worker concurrency | mitigate | `NOODARA_WORKER_CONCURRENCY` range 1–20 rejects a value that would let one worker open unbounded simultaneous SSH sessions |
| T-4-14 | Information Disclosure | env validation failure output | accept-by-existing-control | `parseTuningInt` feeds `EnvIssue { variable, requirement }`, which by construction never carries the received value (Phase 1 T-1-06); no new code path echoes a value |
</threat_model>
