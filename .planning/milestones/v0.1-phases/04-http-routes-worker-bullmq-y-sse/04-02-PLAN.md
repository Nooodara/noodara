<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/any HTTP client → API | Unauthenticated, attacker-controlled requests and headers reach Fastify |
| service result → HTTP response | Internal failure codes and messages become client-visible bodies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-01 | Spoofing | guarded routes under `/api` | mitigate | `createRequireSession` `onRequest` hook resolves the session through Better Auth's `getSession` and 401s before any handler runs; the guard's inertness outside its Fastify scope is asserted by a sibling-route test |
| T-4-07 | Spoofing / CSRF | mutating routes | mitigate | `createOriginGuard` rejects a present-but-mismatched `Origin` on POST/PATCH/DELETE with 403 `FORBIDDEN_ORIGIN`, strict `===` on the parsed origin; absent Origin allowed for non-browser clients (D-29) |
| T-4-04 | Information Disclosure | error bodies | mitigate | `toErrorBody` builds `{ error, message }` field by field and never spreads an error object; `toValidationErrorBody` copies only `path` and `message` from a Zod issue, dropping `received`/`expected` which would echo submitted input |
| T-4-15 | Elevation of Privilege | `request.actor` | mitigate | `actor` is decorated `null` and only ever assigned from the resolved session's `user.id` inside the hook — no route may construct an actor from request input; `ServiceActor` is imported, never redeclared |
| T-4-16 | Tampering | status mapping drift | mitigate | `SERVICE_ERROR_STATUS` is frozen and `satisfies Record<ServiceErrorCode, number>`; a static scan of the service sources fails the build if a new failure code is unmapped |
</threat_model>
