| Operator environment → control plane | Timeout values are operator-supplied integers that bound every remote operation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-09 | Denial of Service (availability) | Migration 0002 in-place upgrade | mitigate | `ADD COLUMN IF NOT EXISTS`, no NOT NULL, no DEFAULT; the from-snapshot test applies 0001, seeds a populated `servers` row with a pinned fingerprint, applies 0002 via the production `runMigrations`, and asserts field-identical survival plus NULL backfill |
| T-2-10 | Denial of Service | Unbounded or absurd SSH timeouts | mitigate | Explicit inclusive ranges per knob plus a discovery >= command coherence rule; a value outside the range fails the boot rather than producing a worker that hangs for hours on one server |
| T-2-11 | Information Disclosure | `NOODARA_CONFIG_ERROR` stderr lines in CI logs | mitigate | `EnvIssue` still carries no `received` field (the existing T-1-06 mitigation); an acceptance criterion asserts the rejected value does not appear in the requirement string |
| T-2-12 | Spoofing | Fingerprint provenance after a host-key change | mitigate | `host_fingerprint_captured_at` and `pending_fingerprint_seen_at` let the operator see when each key was observed before trusting a new one (D-06), instead of comparing two undated strings |
</threat_model>
