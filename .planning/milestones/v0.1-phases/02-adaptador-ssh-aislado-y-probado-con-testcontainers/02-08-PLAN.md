<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote server → adapter process | Everything the remote end sends — host key, auth challenges, error conditions, socket closes — is untrusted input to the adapter's control flow |
| Adapter → worker process (phase 4) | An unhandled rejection or an unhandled `'error'` event inside the adapter takes down the process that runs it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-31 | Spoofing | `client.connect` options construction | mitigate | Options are built in one named function and a test asserts `hostVerifier` is always present, `hostHash` is always absent, and the host key algorithm list is the exact D-05 ordering — the direct guard against 02-RESEARCH.md's Pitfall 1 |
| T-2-32 | Denial of Service | Unhandled ssh2 `'error'` event after `ready` | mitigate | An error listener is attached before `connect` and kept for the session's lifetime, asserted by a test; every path routes through `classifySshError` and returns a value |
| T-2-33 | Spoofing | Operator trusting a changed host key without verifying | mitigate | The `HOST_KEY_CHANGED` message renders both fingerprints with their key types (D-06) and states the out-of-band verification step; the adapter offers no trust action of its own |
| T-2-34 | Denial of Service | Retry storm against a rate-limiting sshd | mitigate | Exactly one retry, only for the two transient codes, after a fixed 2s wait; `AUTH_FAILED`/`HOST_KEY_CHANGED`/`HOST_UNRESOLVED`/`COMMAND_TIMEOUT` are never retried (D-10, PITFALLS.md 8) |
| T-2-35 | Denial of Service | Concurrent connections exhausting sshd's MaxStartups | mitigate | Per-target mutex keyed on user@host:port with release in a `finally`; the global concurrency limit is deliberately deferred to the phase 4 worker |
| T-2-36 | Information Disclosure | Credential reaching a log through the connect options | mitigate | `revealSecret(secret, redactor)` registers the plaintext with the caller's live redactor at reveal time, so any later log/error/output in the same operation is scrubbed; the adapter constructs no redactor of its own |
</threat_model>
