<objective>
Implement the two security controls the whole phase rests on: credential loading with a real format/type policy, and TOFU host verification with no bypass.

Purpose: SEC-03 is a security control, and 02-RESEARCH.md's Pitfall 1 names the exact way it degrades — a `hostVerifier` that returns `true`, or is simply absent, and everything appears to work. ADR 0004 (plan 02-04) has already measured how the raw host key reaches the verifier and proven the fingerprint derivation matches `ssh-keygen -lf`; this plan turns that measurement into the module, plus the tests that make a silent downgrade impossible to merge.
Output: `key-loader.ts`, `fingerprint.ts`, `host-verifier.ts`, and a per-run key generator so no key material is ever committed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote host key → Noodara's trust decision | The host key blob is attacker-controlled input in a MITM scenario; the fingerprint derived from it is the only thing standing between the operator and a spoofed server |
| Decrypted credential → adapter memory | A plaintext private key and passphrase exist in process memory while loading, and any error path is a potential exfiltration channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-21 | Spoofing | `createHostVerifier` | mitigate | No bypass option exists (asserted by a grep gate and by the factory's option keys); a mismatch returns `false` for all three key types; the digest derivation is cross-checked against real `ssh-keygen -lf` output by plan 02-04's standing integration test (Pitfall 1 / PITFALLS.md 4) |
| T-2-22 | Spoofing | Key-type substitution with a colliding-looking digest | mitigate | `fingerprintsEqual` compares type and digest; a same-digest/different-type pair is a mismatch, which is exactly D-05's rule |
| T-2-23 | Information Disclosure | `utils.parseKey` error messages | mitigate | `parseKey`'s `Error.message` is never propagated (grep gate); the loader emits a fixed set of project-authored messages, and a test proves no message changes under a `Redactor` that has the key and passphrase registered |
| T-2-24 | Elevation of Privilege | Weak RSA key accepted | mitigate | Modulus size read from the parsed key and rejected below 2048 (D-01), before any socket is opened |
| T-2-25 | Denial of Service | Malformed host key blob | mitigate | The RFC 4253 length prefix is validated against the buffer length before slicing; a malformed blob is a validation failure, not an out-of-bounds read or a throw inside ssh2's callback |
</threat_model>
