<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| control-plane process → PostgreSQL | Credentials at rest live here; the schema decides whether a DB dump is catastrophic or inert |
| Operator upgrade → migration runner | A half-applied migration puts the control plane in a crash loop (Coolify #2820) |
| Unauthenticated first visitor → setup_tokens | Whoever redeems a valid token becomes the only admin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-16 | Information Disclosure | `credentials` table | mitigate | Only `encrypted_value` plus `key_version` columns exist; there is no plaintext column to accidentally populate, and the blob format is the authenticated AES-256-GCM envelope from Plan 01-05 (SEC-01, D-10) |
| T-1-17 | Elevation of Privilege | `setup_tokens` table | mitigate | Only `token_hash` is stored; `used_at` plus a partial unique index on unused, unexpired tokens per purpose gives a database-level backstop against the setup-token race in addition to the application check in Plan 01-12 (D-01, D-02) |
| T-1-18 | Denial of Service (availability) | Migration runner | mitigate | Defensive SQL (`IF NOT EXISTS`, guarded `CREATE TYPE`, no unguarded `DROP`), idempotence proven by a second consecutive run, non-interactive execution verified with stdin closed (PITFALLS.md #10, QA-06) |
| T-1-19 | Information Disclosure | Migration failure output | mitigate | `migrate.ts` logs the error message but never the connection string or `DATABASE_URL` |
</threat_model>
