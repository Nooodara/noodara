<objective>
Implement AUTH-04's rate limiting the way D-07 specifies, which Better Auth cannot do natively.

RESEARCH is unambiguous here: Better Auth's `rateLimit` keys on IP and path only (`createRateLimitKey(ip, path)` in its own source) and has no progressive backoff. Treating it as AUTH-04 coverage would under-deliver the requirement. Better Auth's limiter stays on as a coarse per-path guard; the real mechanism is a Postgres-backed counter with independent IP and account scopes and a doubling window.

Purpose: the single admin account is the only credential in the product. Brute-force containment that never permanently locks the admin out is the shape D-07 requires — the admin always recovers by waiting or by running `noodara admin reset` (Plan 01-14).
Output: pure backoff arithmetic in the domain, the persistence layer, the guard hooks, and an integration suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unauthenticated internet → `POST /api/auth/sign-in/email` | The single admin credential is the only thing between an attacker and every registered server |
| Reverse proxy → Fastify client IP resolution | A forwarded header is attacker-controlled unless the proxy is explicitly trusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-39 | Elevation of Privilege | Credential brute force / stuffing | mitigate | Independent per-IP and per-account counters in `login_attempts` with a 5-per-15-minute threshold and a doubling lockout capped at 24 hours, enforced before the password is verified (D-07, AUTH-04) |
| T-1-40 | Spoofing | Per-IP counter bypass via `X-Forwarded-For` | mitigate | The forwarded header is honoured only when `NOODARA_TRUST_PROXY` is explicitly enabled; a test asserts it is ignored by default |
| T-1-41 | Denial of Service | Attacker locking the admin out permanently | accept (bounded) | The lockout is capped at 24 hours and never permanent, and `noodara admin reset` (Plan 01-14) gives an out-of-band recovery path — D-07 accepts the temporary-denial tradeoff explicitly |
| T-1-42 | Information Disclosure | Failed-login activity metadata | mitigate | Written through the single activity writer, which redacts and whose domain builder throws on a `password` key; asserted by test (AUTH-04) |
| T-1-43 | Information Disclosure | Account enumeration via response differences | accept | A single-admin instance has no meaningful enumeration surface; the 429 is identical whether or not the email matches the admin |
</threat_model>
