<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| real remote server → control plane | Discovery output from an actual sshd crosses into logs, snapshots and API responses |
| every new surface added this phase → client | HTTP bodies, SSE frames and log lines are all potential leak channels |
| unauthenticated network → `/health` | The liveness surface is reachable without a session by design |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-05 | Information Disclosure | every response body and SSE frame | mitigate | `canary-http.test.ts` submits per-run random canaries through the real routes and asserts their absence across success bodies, error bodies, SSE frames, logs, `activity_events.metadata` and `discovery_snapshots.payload`, with a non-vacuity guard and a verified deliberate-break |
| T-4-04 | Information Disclosure | forced 500 on a live route | mitigate | The canary suite forces an unhandled exception while a canary is registered and asserts the opaque body plus the redacted log, exercising Plan 04-04's production error handler rather than a test-local one |
| T-4-43 | Repudiation | unverified phase claims | mitigate | The validation map is completed with real task ids and honest statuses; sign-off boxes may only be ticked when true, and `nyquist_compliant` is set from evidence |
| T-4-41 | Information Disclosure | `/health` after a worker death | mitigate | The degraded case asserts the body still carries only `pass`/`fail` literals and the version — no error text, no connection detail |
| T-4-44 | Denial of Service | operational blind spot | mitigate | The boot smoke proves `/health` distinguishes a live worker from a dead one, which is what Phase 6's Compose healthchecks and restart policy will key on |
</threat_model>
