<objective>
Give the Phase 3 services a publication port so a state change announces itself wherever it happened — HTTP route, worker or a future CLI — without the caller having to remember. This is the producer half of the SSE bridge; the Redis adapter and the stream itself land in Plan 04-09.

Purpose: D-04's "the service publishes, not the caller" is what makes `CONNECTING` visible the instant the worker picks up a job, with no duplicated publish logic in two processes.
Output: `events/server-event-publisher.ts`, `deps.events`, six publish sites, one integration proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database row → event payload | A `servers` row (which sits next to an encrypted credential) becomes a payload destined for a browser stream |
| service → out-of-process consumer | An event leaves the transaction's consistency guarantees |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-05 | Information Disclosure | `server.updated` payload | mitigate | The event carries `toServerView(...)`'s output verbatim — the same 27-field explicit allowlist that already guards `GET /api/servers/:id`; a test asserts the published payload's key set equals `SERVER_VIEW_KEYS`, so a future `servers` column cannot leak into the stream just by existing |
| T-4-17 | Repudiation | publish-before-commit | mitigate | Every publish call sits after its `db.transaction(...)` resolves, asserted by a test that records zero events for a failing transaction — a rolled-back change can never announce itself as fact |
| T-4-18 | Denial of Service | a failing publisher aborting real work | mitigate | `publishServerEvent` swallows any rejection or synchronous throw, and an integration test asserts `registerServer` still returns `ok: true` and still commits when the injected publisher rejects (D-04) |
| T-4-19 | Information Disclosure | `server.deleted` payload | mitigate | Carries only `{ id }` — no name, host or any other attribute of a server the admin just removed |
</threat_model>
