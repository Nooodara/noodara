<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → `/api/servers*` | Attacker-shaped bodies, params and credential material cross into the control plane |
| service result → response body | Rows adjacent to encrypted credentials become client-visible JSON |
| route → queue | A request triggers work that will later hold a decrypted credential in another process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-05 | Information Disclosure | every `/api/servers` response | mitigate | Responses are `ServerViewSchema`, asserted key-for-key against `SERVER_VIEW_KEYS`; a canary test scans the raw body string of every status for the submitted private key, passphrase and password |
| T-4-33 | Tampering | request bodies | mitigate | `.strict()` Zod schemas on create and update, `z.uuid()` on the id param, all validated before any service call; unknown keys are rejected rather than silently forwarded |
| T-4-01 | Spoofing | all eight routes | mitigate | Registered inside `api-scope.ts`, so `requireSession` 401s anonymous callers before any handler runs; a test asserts 401 for each route |
| T-4-07 | Spoofing / CSRF | POST/PATCH/DELETE | mitigate | The scope's `createOriginGuard` hook rejects a mismatched browser `Origin` with 403 before the handler |
| T-4-08 | Denial of Service | Redis outage | mitigate | `enqueue`'s bounded failure becomes 503 `QUEUE_UNAVAILABLE` through the status map; reads and CRUD keep serving from Postgres, asserted in the same test |
| T-4-34 | Denial of Service | duplicate connect storms | mitigate | Deterministic `jobId` makes a repeated POST idempotent, and Phase 3's `SELECT ... FOR UPDATE` rejects a second in-flight attempt with `ALREADY_CONNECTING`; D-30's "no rate limit in v0.1" rests on exactly these two |
| T-4-35 | Information Disclosure | enqueue logs | mitigate | The info log carries `serverId`, `jobId` and `trigger` only — never the body, never the credential, never the host |
</threat_model>
