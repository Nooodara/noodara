<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| control plane → DNS resolver | An outbound query for a user-supplied domain |
| authenticated client → current-password check | A holder of a session cookie can guess the current password |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Spoofing / brute force | current-password confirmation on /api/account/* | high | mitigate | Task 2: ReauthGuard progressive lockout (5 attempts / 15 min window, escalating backoff). Wired into every account endpoint by 09-06 and 09-09 |
| T-09-20 | Denial of service | stolen session locking the admin out of sign-in | medium | mitigate | Task 2: a separate `reauth:<userId>` key; the email-keyed login lockout row is never touched |
| T-09-02 | Denial of service | DNS lookup hang | high | mitigate | Task 1: EMAIL_DOMAIN_LOOKUP_TIMEOUT_MS = 3000 race, resolver timeout 2000 / tries 1, timer always cleared, never throws |
| T-09-21 | Tampering / SSRF-ish | resolver abuse via crafted domain | low | mitigate | Task 1: a hostname shape check before any query; no user-controlled resolver servers; only MX/A queries, and no connection is ever opened to the resolved host |
| T-09-15 | Denial of service (self) | resolver down blocks email changes | low | mitigate | Task 1: a distinct 'unavailable' outcome, so 09-06 can show an honest "couldn't check right now" error instead of claiming the domain is invalid |
