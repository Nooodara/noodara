<objective>
Build the review package the approval gate (07-05) needs: a static brand board per concept and theme, and an in-app capture script that shows each concept mounted in the real Noodara shell and auth screens in both themes — without modifying `Sidebar.tsx`/`AuthCard.tsx`. Mechanism chosen: **DOM injection at capture time** (`page.evaluate` + `insertAdjacentHTML` of `renderStaticSvg` markup with `fill="currentColor"` inside a `color: var(--ink)` wrapper). Why: a `?brand=` query flag or env switch would require production code to read it (a trace), whereas injection is confined to the script, uses the exact markup the components emit, inherits the real theme tokens, and disappears when the page reloads.

Purpose: D-14 says the board alone is not enough — the user approves in real context. This plan makes that context reproducible for three concepts and up to two adjustment rounds.

Output: `scripts/brand/{board-html,render-boards,capture-brand-review,review-paths}.ts`, two unit tests, `docs/brand/review/README.md`, `.gitignore` entries, root scripts `brand:boards` and `brand:review`, and — run once at the end — `docs/brand/review/<a|b|c>/*.png` on disk (ignored).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| capture script → real app in a browser | The script logs in with fixture (or operator-provided) credentials and injects markup into the live DOM |
| screenshots → filesystem / possibly shared with the user | PNGs of /login, /setup and the shell could capture sensitive content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 | Information Disclosure | screenshots | mitigate | `/login` and `/setup` are captured with EMPTY fields before any typing; credentials are typed only after those captures and never appear on screen; the shell captures show fixture data only (E2E stack) or the operator's own dev stack; no capture of the browser chrome (Pitfall 2) |
| T-07-10 | Information Disclosure | script logs | mitigate | Credentials come from `startStack()` or env and are never passed to `console.*`; acceptance criterion greps for it |
| T-07-11 | Tampering | DOM injection | mitigate | Injected markup is `renderStaticSvg` output (tested in 07-03 to contain no script/handlers); injection helper is script-scoped; page reloads between surfaces; never used outside review; production mount in 07-07 uses React components, not this path |
| T-07-12 | Spoofing | attach mode (`BRAND_REVIEW_BASE_URL`) | accept | Operator-controlled local URL only; documented as `http://localhost:3000`; no default value |
| T-07-SC | Tampering | npm installs | accept (n/a) | No new packages; Playwright already a devDependency |
</threat_model>
