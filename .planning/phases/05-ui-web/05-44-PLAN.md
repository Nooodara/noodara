<interfaces>
Backend side — `apps/control-plane/src/routes/http-errors.ts`:
- `toValidationErrorBody(issues)` returns `{ error: 'VALIDATION_FAILED', message: 'Request does not match the schema', issues: [{ path, message }] }`, copying ONLY `path` and `message` from each raw issue (T-4-04: a raw Zod issue can echo submitted input).
- `normalizeIssuePath` prefers `instancePath` (AJV/`@fastify/type-provider-zod` shape, e.g. `/name`, `/credential/password`) and falls back to a dot-joined `path` array.
- The body is produced by `app.setErrorHandler` in `apps/control-plane/src/app.ts` via `hasZodFastifySchemaValidationErrors`, so it only exists for SCHEMA-level rejections. Service-level rejections (`validateSshUser`, `validateHost`) return `{ error: 'VALIDATION_FAILED', message }` with NO `issues` array — that is why the sshUser E2E had to stub, and it is worth recording in the SUMMARY.

Frontend side — `apps/web/src/lib/error-copy.ts`:
- `KNOWN_FORM_FIELD_PATHS` = token, email, password, name, host, sshPort, sshUser, credential.
- `normalizeFieldPath(path)` splits on `/`, drops empties, maps any first segment `credential` (bare or nested) onto `'credential'`, maps a single-segment path onto itself, and returns `null` for anything else or anything outside `KNOWN_FORM_FIELD_PATHS`.
- `fieldErrorsFromIssues(issues)` maps issues to `{ formKey: message }`, first message wins per key, `null` normalizations dropped.
- **This module is runtime-dependency-free**: its only two imports are `import type` (from `./api-client` and `@noodara/domain/server`), so they are erased at runtime. It can be imported from an integration test without pulling in React, Next.js or any browser API.

Request schema — `apps/control-plane/src/routes/server-schemas.ts`, `CreateServerBodySchema`: `.strict()` over `name: z.string().min(1)`, `host: z.string().min(1)`, `sshPort: z.number().int().optional()`, `sshUser: z.string().min(1).optional()`, `credential: WireCredentialSchema` (a strict discriminated union on `type`, with `password: z.string().min(1)` / `privateKey: z.string().min(1)`).

Harness — `tests/integration/helpers/app.js` exposes `startTestApp()` returning `{ app, db, stop }`. `tests/integration/servers/trust-fingerprint-binding.test.ts` is the cleanest current example of the full boot → `POST /api/setup` → sign-in → cookie → `app.inject` flow, including the stray-container assertion in `afterEach`. Reuse that shape; do not invent a new harness.

Import style for the cross-app import: integration tests already import control-plane source by relative path with a `.js` extension (e.g. `'../../../apps/control-plane/src/db/schema/index.js'`). Use the same form for `'../../../apps/web/src/lib/error-copy.js'`. `vitest.integration.config.ts` aliases `@noodara/domain` to source, which covers the type-only import.
