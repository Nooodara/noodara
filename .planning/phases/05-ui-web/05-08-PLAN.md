<objective>
Build the input and overlay half of the design system: `Input`, `Textarea`, `Field`, `SegmentedControl`, `FileButton`, `Sheet` and `Dialog`.

Purpose: these are the components the add/edit sheet (D-01, D-04), the delete confirmation (phase-3 D-12) and the trust-new-fingerprint dialog (D-03) are made of — and the three places where a credential could leak into a URL, a file upload or the browser's password manager. Building them once, on Radix, with the security rules baked in, is what keeps those rules out of individual screens.
Output: seven components plus one unit-tested pure predicate, exported from the barrel.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → browser memory → API request body | A private key crosses from disk into a form field; any detour through a URL, storage or a log is a credential leak |
| user keystrokes → destructive action | A weak confirmation gate turns a misclick into an irreversible delete or a trusted impostor host key |
| browser password manager → credential fields | Autofill offering to save an SSH key as a website login |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-31 | Information Disclosure | `FileButton.tsx` | mitigate | `FileReader.readAsText` only; grep-enforced absence of `localStorage`, `sessionStorage`, `console.`, `FormData` and `multipart`; read errors surface a fixed generic message |
| T-5-32 | Information Disclosure | credential inputs and browser autofill | mitigate | `Input`/`Textarea` forward `autoComplete`, documented so credential usages pass `off` while the login form keeps its legitimate values (enforced at the call site in Plans 05-11 and 05-17) |
| T-5-33 | Elevation of Privilege | `DestructiveConfirmDialog` | mitigate | Exact-match gate via the unit-tested `isConfirmationMatch`; the API's `CONFIRMATION_MISMATCH` stays the enforced check and has an inline error slot |
| T-5-34 | Tampering | overridden Radix accessibility behaviour | mitigate | Grep gate asserting no `onEscapeKeyDown`, `onInteractOutside` or `outline: none` anywhere in `packages/ui/src` |
| T-5-35 | Information Disclosure | error text rendered in a field | mitigate | `Field`'s error slot renders a caller-supplied string only; the API `message` is the only source (client never composes from an exception) |
| T-5-SC | Tampering | `pnpm add` of seven `@radix-ui/react-*` packages | mitigate | All seven in ADR-0000's Phase 5 additions table; provenance script re-run in Task 1's verify |
</threat_model>
