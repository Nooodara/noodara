`scripts/check-package-provenance.mjs` has exactly two `execFileSync` calls:
- `enumerateLockedDependencies()` at ~line 244: `execFileSync('pnpm', ['list', '-r', '--depth', '0', '--json'], { encoding: 'utf8' })` — its failure is fatal to the script (no try/catch around it).
- `resolvePackageProvenance()` at ~line 277: `execFileSync('npm', ['view', spec, 'repository.url'], { encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] })` — already wrapped in a try/catch that falls back to the registry JSON API.

Node's `execFileSync` `timeout` option kills the child with `SIGTERM` after the given milliseconds and throws; for the `npm view` call, that throw lands in the EXISTING catch and takes the registry-API fallback, which is the desired behaviour (one slow package must not fail the gate). For the `pnpm list` call there is no fallback — a timeout there must produce a clear, actionable failure message naming the command and the timeout.

`tests/integration/helpers/boot-process.ts`:
- `buildValidBootEnv(connectionString, redisUrl)` at ~line 35 already sets `env.NOODARA_API_ORIGIN = 'http://localhost:3100'` for SPAWNED BOOT PROCESSES — so the boot processes themselves are fine.
- `buildWorkspace()` at ~line 186 is the actual defect: `spawnSync('pnpm', ['build'], { cwd: repoRoot, stdio: 'inherit' })` with no `env`, so the child inherits whatever the developer's shell has. `apps/web/next.config.ts` (~line 14) throws `NOODARA_API_ORIGIN is required (...)` and `next build` exits non-zero.
- `buildWorkspace()` is called by `tests/integration/global-setup.ts` (so the ENTIRE integration run dies at setup), by `tests/integration/boot/boot-command.test.ts` (~line 294), and by `tests/e2e/fixtures/stack.ts` (~line 112 — that caller already sets `process.env.NOODARA_API_ORIGIN` at ~line 108 first, which is why E2E does not hit this).

`.env.example` already documents `NOODARA_API_ORIGIN` at length, including the dev value `http://localhost:3100` and the reason mixing it up with `NOODARA_PUBLIC_URL` causes 403 `FORBIDDEN_ORIGIN`. Do not duplicate that text; reference it.

**The production rule must not weaken.** `apps/web/next.config.ts`, `apps/web/src/proxy.ts` and `apps/web/src/app/api/events/route.ts` each fail fast on a missing `NOODARA_API_ORIGIN` (docs/adr/0006, INST-06: "No variable here has a default anywhere in the codebase"). The default added by this plan lives ONLY in the test helper that spawns a build, and must be commented as such.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-5G-42-01 | Denial of Service | `execFileSync('npm', ['view', ...])` hanging on an unresponsive registry | mitigate | `timeout: 30_000`; the throw lands in the existing catch and takes the registry-API fallback, so one slow package does not fail the gate |
