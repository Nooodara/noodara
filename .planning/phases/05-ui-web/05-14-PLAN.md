<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| discovered facts (hostname, OS strings) → rendered DOM | Values originating from a remote server the admin does not fully control |
| fingerprint row → clipboard | A copy affordance next to security-relevant material |
| toolbar action → state-changing POST | A mutating request triggered from a read-oriented screen |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-59 | Tampering | rendering remote-origin fact strings | mitigate | React escaping only; the repo-wide no-raw-HTML grep gate (Plan 05-21) covers this file |
| T-5-60 | Information Disclosure | credential exposure on the detail screen | mitigate | Only `credentialType` is rendered; `ServerView` structurally cannot carry a credential value (SEC-02), and a component test asserts no `privateKey`/`password`/`passphrase` label or value appears in the render |
| T-5-61 | Spoofing | a snapshot read as a live metric | mitigate | Every tile and group value carries an explicit "as of {time}" caption, asserted for every tile and row in the component test and again in the browser spec |
| T-5-62 | Tampering | mutating POST from the toolbar | mitigate | Issued through the api client, so same-origin credentials and a relative `/api/` URL are structural; the API's Origin guard remains the enforcing control |
| T-5-63 | Information Disclosure | fingerprint copy button | accept | The host fingerprint is public information by design (it is what the admin verifies on the server with `ssh-keygen -lf`); no credential is ever copyable |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
