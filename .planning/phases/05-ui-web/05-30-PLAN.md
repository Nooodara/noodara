## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| control plane `issues[]` → rendered field labels | Backend-controlled strings and paths crossing into the DOM |
| `/setup?token=…` → address bar, history, Referer header | A single-use install credential living in a URL |
| browser → outbound navigation from `/setup` | The Referer header is the leak channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5G-30-01 | Information Disclosure | setup token in URL/history | mitigate | `history.replaceState` strips `token` after the mount-time read; E2E asserts `page.url()` has no `token=` |
| T-5G-30-02 | Information Disclosure | setup token in a `Referer` header | mitigate | `Referrer-Policy: no-referrer` from `next.config.ts` `headers()`; E2E asserts the literal header |
| T-5G-30-03 | Information Disclosure | rendering unknown backend issue paths | mitigate | `normalizeFieldPath` returns `null` for unrecognised paths and `KNOWN_FORM_FIELD_PATHS` stays an allowlist of form keys; a test asserts an unknown path is dropped |
| T-5G-30-04 | Spoofing | misleading failure copy sending the admin down the wrong recovery path | mitigate | Four-way branch: token / validation / network / other, each with its own vocabulary-bounded string |
| T-5G-30-05 | Information Disclosure | token value in logs or test output | mitigate | Synthetic fixture value only; no `console.*`, no `data-*` carrying the token; todo item 3 (web-side access logs) verified and reported |
| T-5-30-SC | Tampering | npm/pnpm installs | mitigate | NO new dependency. If one seems necessary, stop and report. |
