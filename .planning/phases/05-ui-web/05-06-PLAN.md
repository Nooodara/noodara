<objective>
Create `packages/ui`: the token layer and the first two components of the Noodara design system, plus the monorepo wiring (build, boundaries, lint, barrel) every later UI plan builds on.

Purpose: UI-01 requires the shell and every screen to draw exclusively from the locked `noodara-ux-apple` token set. Making the tokens a real CSS artifact and the first two components real, before any screen exists, is what stops later plans from inventing values.
Output: a building, lint-clean, boundary-tagged `@noodara/ui` with `tokens.css`, a Tailwind v4 `@theme` binding, `Button`, `StatusPill`, two unit-tested pure helpers, and an ADR recording the component-verification strategy.

**Verification strategy decision (record it in the ADR):** component rendering in this phase is verified by Playwright against the real app (Plans 05-10 onward), and pure logic modules by Vitest. This deliberately avoids four net-new dev dependencies (`jsdom`/`happy-dom`, `@testing-library/react`, `@testing-library/jest-dom`, a React Vitest transform plugin) that appear nowhere in 05-RESEARCH.md's Package Legitimacy Audit, following the same "no new tooling unless necessary" precedent that declined `concurrently` in Phase 4. Consequence to state plainly in the ADR: until Plan 05-10 lands, `packages/ui` components are verified by build, lint, typecheck and their pure helpers only.
</objective>
