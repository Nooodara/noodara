<objective>
Close the CONNECTING wedge (VERIFICATION gap 2, backend half; 05-REVIEW.md WR-A-01). `connectAndDiscover` currently commits `CONNECTING` in TX1 and then runs `decodeCredential`, `parseFingerprint`, the SSH phase, `session.close()` and TX2 with no `try/catch` around them. The worker's `'failed'` listener only logs. A throw from any of those (a credential that no longer decodes after a master-key rotation is the realistic one) leaves the row in `CONNECTING` until a worker restart's sweep.

Purpose: a wedged `CONNECTING` is not one of DETL-02's two named states and offers the admin no action at all — every mutation is refused as `SERVER_BUSY`. The detail screen renders it as an endless "Connecting…", which is exactly the "generic spinner" DISC-02/D-05 forbid, reached from the ordinary path rather than an exotic race.
Output: a recovery path on both sides (service-level catch, worker-level `'failed'` listener), plus the integration tests that fail before the fix.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BullMQ/Redis → worker process | Job payloads are attacker-influencable if Redis is reachable; already parsed through `parseConnectServerJobPayload` |
| encrypted credential store → `decodeCredential` | Plaintext credential material exists only inside the newly-wrapped try block |
| service/worker → `activity_events.metadata` and logs | Recovery writes a row and a log line on a failure path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5G-26-01 | Denial of Service | `servers.status` stuck at CONNECTING | mitigate | Post-TX1 catch + `'failed'` listener both call `failInFlightConnection`; integration test asserts the row leaves CONNECTING |
| T-5G-26-02 | Information Disclosure | catch block logging | mitigate | Only `{ jobId, err }` through pino's `err` serializer and the existing redactor; never `job.data`, never the decoded credential, never `err.message` interpolated into a string |
| T-5G-26-03 | Information Disclosure | `activity_events.metadata` | mitigate | `reason` stays a fixed enum literal (`connect_service_threw` / `worker_job_failed`); no free-text or exception detail enters metadata |
| T-5G-26-04 | Tampering | double recovery writing the row twice | mitigate | `failInFlightConnection`'s existing row lock + `skipped` result; Task 1 asserts idempotency |
| T-5G-26-05 | Elevation of Privilege | recovery re-running SSH | accept/mitigate | `failInFlightConnection` never reconnects (D-12) and `maxStalledCount: 0` is unchanged — asserted by the existing queue tests |
| T-5-26-SC | Tampering | npm/pnpm installs | mitigate | This plan adds NO dependency. If one becomes necessary, stop and route through the package-legitimacy checkpoint; do not install. |
