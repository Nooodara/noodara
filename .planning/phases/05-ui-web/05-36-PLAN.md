<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party GitHub Action → CI runner with repo scope | A mutable tag lets an action's code change under a pinned-looking reference |
| npm registry → the dependency tree | Typosquats and compromised publishers enter here; the provenance gate is the check |
| release CDN → CI runner shell | `curl \| tar` executes unverified remote bytes with runner privileges |
| CI secrets (`GITHUB_TOKEN`, `GITLEAKS_LICENSE`) → job steps | Over-broad job permissions widen the blast radius of any compromised step |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5G-36-01 | Tampering | third-party actions | mitigate | Every `uses:` pinned to a commit SHA with the tag in a comment; asserted by grep |
| T-5G-36-02 | Tampering | `curl \| tar` for the gitleaks binary | mitigate | Download, verify SHA256 against the published checksum (or a pinned literal), then extract; asserted by grep that no fetch pipes into a shell or extractor |
| T-5G-36-03 | Elevation of Privilege | default job token scope | mitigate | Per-job least-privilege `permissions:` blocks |
| T-5G-36-04 | Denial of Service | a hung job consuming the runner budget | mitigate | `timeout-minutes` on every job, sized above the real observed cost |
| T-5G-36-05 | Tampering | supply chain — dependencies outside the provenance gate's hardcoded list | mitigate | Lockfile-driven enumeration at the locked version; `ssh2`, `argon2`, `better-auth`, `pg`, `fastify`, `pino`, `zod` now covered |
| T-5G-36-06 | Spoofing | a publisher-asserted `repository.url` | accept | Documented limitation in the script header and `docs/ci-readiness.md`; closing it needs npm provenance attestations, which is out of this gap closure's scope |
| T-5G-36-07 | Repudiation | claiming QA-04/QA-05 complete without a real run | mitigate | `docs/ci-readiness.md` records the exact human observation required; REQUIREMENTS.md untouched; the item re-surfaces in plan 05-37's checkpoint |
| T-5-36-SC | Tampering | npm/pnpm installs | mitigate | NO new dependency. The YAML validation uses macOS's bundled `python3` or an already-installed parser — never `pnpm dlx`/`npx --yes`. |
</threat_model>
