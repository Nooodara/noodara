<interfaces>
Endpoints these screens call (verified against source, 2026-09-19):

`POST /api/setup` with body `{ token: string, email: string, password: string }` → 200 `{ success: true }`, or 400/404 `{ error, message }`. The 404 is the already-has-an-admin gate and must not be distinguishable in the UI from a bad token.
`POST /api/auth/sign-in/email` (Better Auth, proxied under `/api/auth/*`) → sets the session cookie on success; 401 on bad credentials; 429 with a `Retry-After` header when the progressive lockout is active.
`POST /api/auth/sign-out` clears the session.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated visitor → `/setup` and `/login` | The only two screens an attacker can reach; both are account-and-token existence oracles if worded carelessly |
| password field → network | Plaintext credential in browser memory and in one request body |
| `Retry-After` header → rendered text | Server-controlled value reaching the DOM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-45 | Information Disclosure | login error copy | mitigate | One fixed invalid-credentials string for every 401 cause; E2E asserts the exact copy and that the submitted email never appears in the page text |
| T-5-46 | Information Disclosure | setup failure copy | mitigate | 400-without-issues, 404 and unexpected failures all render one identical message; a code comment records why they must not be distinguished |
| T-5-47 | Information Disclosure | password in URL, storage or console | mitigate | Grep gate asserting zero `console.`, `localStorage` and `sessionStorage` in both page files; the post-login redirect target comes from a query parameter, never the credential |
| T-5-48 | Brute force | login form | transfer | The progressive lockout is enforced server-side (phase 1 D-07); the UI only renders the 429 with its `Retry-After` and never retries automatically |
| T-5-49 | Tampering | `Retry-After` value rendered | mitigate | Parsed to a number and formatted as a duration; a non-numeric header degrades to the generic wait copy rather than being echoed |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
