<objective>
Close the domain-layer root cause of 05-VERIFICATION.md gap 6 (GR-01): `applyConnectionResult` currently carries a parked `pendingFingerprint` forward through a later successful connect and through every later failure whose code is not `HOST_KEY_CHANGED`, which is what makes a stale fingerprint promotable at all.

Purpose: the backend gate added in plan 05-39 refuses a promotion whose current failure is not a host-key mismatch. That gate is a boundary check; this plan removes the stale state it would otherwise have to guard forever. Both are required — CLAUDE.md §2.3.

Output: `applyConnectionResult` clears `pendingFingerprint` on `ok:true` and on any `ok:false` whose `errorCode !== 'HOST_KEY_CHANGED'`, with unit coverage that actually starts from a non-null parked value (today's suite never does), plus the persistence-layer change that writes NULL into `pending_fingerprint_seen_at` whenever the value itself is cleared.
</objective>

<interfaces>
`ServerConnectionState` (packages/domain/src/server/connection-result.ts) owns exactly five fields: `status`, `lastErrorCode`, `hostFingerprint`, `pendingFingerprint`, `lastSeenAt`. It deliberately does NOT own `pendingFingerprintSeenAt` or `hostFingerprintCapturedAt` — those two timestamps are the service's job (connect-and-discover.ts's "Pitfall 4" comment). Do not add them to the domain interface.

`ConnectionResult` is `{ ok: true; fingerprint: string } | { ok: false; errorCode: ServerErrorCode; observedFingerprint?: string }`.

`SERVER_ERROR_CODES` = AUTH_FAILED, HOST_UNRESOLVED, CONNECT_TIMEOUT, COMMAND_TIMEOUT, HOST_KEY_CHANGED, CONNECTION_LOST, UNSUPPORTED_OS. Note `UNSUPPORTED_OS` is an `ok:false` result that lands on `CONNECTED` (D-11) — it is a non-HOST_KEY_CHANGED outcome and therefore clears the parked value like the rest.

`connection-result.test.ts`'s `buildState()` defaults `pendingFingerprint` to `null`, which is precisely why this gap had no coverage: no existing case sends a non-null parked value into either branch.

In connect-and-discover.ts, the current `pendingFingerprintSeenAt` local (around line 361) is computed only from the raw `outcome`, falling back to `row.pendingFingerprintSeenAt` — independent of what the domain decided about the value itself. Both `.set({...})` calls (the no-discovery branch and the post-discovery branch) write that same local.

| parked `pending_fingerprint` → `host_fingerprint` (trusted) | The TOFU trust decision; this plan removes the stale-state path into it |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-5G-38-01 | Spoofing | `applyConnectionResult` success branch | mitigate | `pendingFingerprint: null` on `ok:true` — an interceptor's key parked by an earlier HOST_KEY_CHANGED cannot outlive a legitimate reconnect and be promoted later |
