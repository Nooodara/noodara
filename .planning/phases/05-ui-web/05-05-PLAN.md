The wire contract this plan produces, consumed by Plan 05-18:

`GET /api/servers/:id/discovery` → 200 with `{ collectedAt: string | null, outcome: 'ok' | 'partial' | 'failed' | null, checks: DiscoveryCheck[], warnings: ServerErrorCode[] }`, 401 or 404 with `{ error, message }`.

`DiscoveryCheck` on the wire is `{ id, status, detail, durationMs }` — identical to `packages/domain/src/discovery/types.ts`'s interface, with `id` one of the eleven `DISCOVERY_CHECK_IDS` and `status` one of `pass | fail | skipped | not_applicable`.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `discovery_snapshots.payload` (jsonb) → HTTP response | A whole-column pass-through would expose every stored fact and any future payload addition |
| unauthenticated network → the new route | A ninth route is a new chance to land outside the guarded scope |
| browser → `:id` param | Attacker-shaped ids reach a database query |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-18 | Information Disclosure | `services/read-discovery.ts` payload projection | mitigate | Only `checks` and `warnings` are read off the jsonb payload; `facts` and unknown keys are dropped; `DiscoveryReadResponseSchema` is `.strict()` so an extra field fails serialization |
| T-5-19 | Broken Access Control | `GET /api/servers/:id/discovery` | mitigate | Registered inside `routes/api-scope.ts`'s guarded scope, so `requireSession` applies; a 401 case is asserted in the route test |
| T-5-20 | Injection | `:id` param | mitigate | `ServerIdParamSchema` (uuid) validates before the query; Drizzle parameterizes the `where` clause |
| T-5-21 | Information Disclosure | canary coverage gap | mitigate | `canary-http.test.ts` extended to scan the new response body and `server.discovery_progress` frames (QA-05) |
| T-5-22 | Information Disclosure | enumeration of server ids via 404 vs 200 | accept | Single-admin model, all-or-nothing access behind one session; distinguishing an existing from a missing server carries no cross-tenant risk in v0.1 |
| T-5-SC | Tampering | npm installs | mitigate | This plan installs no packages; the supply-chain gate is Plan 05-03 |
</threat_model>
