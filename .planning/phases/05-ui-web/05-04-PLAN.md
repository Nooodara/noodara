<objective>
Make check-by-check discovery progress a real server-side signal: `runDiscovery` reports each check as it completes, and `connectAndDiscover` publishes it as a new, explicitly allowlisted SSE event type.

Purpose: DISC-02 is the one phase-5 requirement whose data does not exist yet. D-05 authorizes exactly this addition and fixes its rules: best-effort publication that never fails a run, an explicitly extended broadcaster allowlist, and an event that carries only the already-redacted `detail`. The UI's hard rule — never show progress it has not received — depends on this being the only source of progress.
Output: an additive `onCheck` callback, a third `ServerEvent` member, a one-line allowlist extension, and the wiring between them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote server stdout → `DiscoveryCheck.detail` | Attacker-controlled command output becomes an SSE payload rendered in the admin's browser |
| Redis channel → API process → browser | A new event type widens what the fan-out will forward |
| discovery loop → publisher | A side channel gains the ability to slow or break a real infrastructure operation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-13 | Information Disclosure | `server.discovery_progress` payload | mitigate | Payload is exactly the existing `DiscoveryCheck` (id, status, detail, durationMs); `detail` is `redactor.redact`-passed inside `runDiscovery` before `onCheck` fires; no facts, no raw output, no credential-adjacent field is carried (canary coverage lands in Plan 05-05) |
| T-5-14 | Tampering | `sse-broadcaster.ts` allowlist | mitigate | Literal string added to `KNOWN_EVENT_TYPES`; a near-miss type test proves no prefix/wildcard matching was introduced |
| T-5-15 | Denial of Service | discovery loop | mitigate | `onCheck` is synchronous, never awaited, and every invocation is wrapped in a swallowing try/catch; publish result is `void`ed so Redis latency cannot stall SSH work |
| T-5-16 | Spoofing | foreign Redis publisher injecting fake progress | accept | Pre-existing, unchanged risk profile for a shared Redis instance; the allowlist limits it to well-formed types only, and progress frames drive no privileged client action (rendering only) |
| T-5-17 | Tampering | XSS via a `detail` string rendered as HTML | mitigate | React's default escaping; the UI plans forbid `dangerouslySetInnerHTML` near discovery/activity text (enforced in Plans 05-18 and 05-21) |
| T-5-SC | Tampering | npm installs | mitigate | This plan installs no packages; the supply-chain gate is Plan 05-03 |
</threat_model>
