<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `ServerView` fields → rendered DOM | Server-controlled strings (name, host) rendered on the most-visited screen |
| SSE frame → list state | A frame can insert or remove a row |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-55 | Tampering | row rendering of name/host | mitigate | React escaping only; no `dangerouslySetInnerHTML` anywhere in `apps/web/src` outside the single reviewed theme script (grep-gated in Plan 05-21) |
| T-5-56 | Information Disclosure | list payload | mitigate | `ServerView`'s 27-field allowlist structurally cannot carry credential material; the client renders fields, never a whole-object dump — asserted by a component test that puts an extra field on an error payload and checks it reaches no part of the DOM |
| T-5-57 | Tampering | forged `server.updated` inserting a row | mitigate | Frames are validated client-side by `parseServerEventFrame` (Plan 05-12) and every reconnect resyncs from `GET /api/servers`, so a forged row cannot persist |
| T-5-58 | Denial of Service | large server list | accept | v0.1 is one admin with dozens of servers and the API deliberately has no pagination (phase 4 D-19); revisit only if that assumption changes |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
