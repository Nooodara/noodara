<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| observed host key → trusted host key | The single most security-critical transition in the product: it decides which machine receives the stored credential |
| admin's visual verification → the real server | The UI's claim about a fingerprint is only trustworthy if the admin can check it independently |
| client-side dismissal state → security posture | A dismissed notice must not weaken anything |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-86 (UF-01) | Spoofing | edit-then-trust promoting a stale fingerprint | mitigate | Server-side fix landed in Plan 05-01; this plan adds the UI-level regression test D-17 requires and asserts `hostFingerprint` is unchanged |
| T-5-87 | Spoofing | admin trusting an impostor host | mitigate | Both surfaces print the `ssh-keygen -lf` command and the exact fingerprint so verification happens on the server, not in the UI; the trust action carries a type-the-name gate identical to delete |
| T-5-88 | Elevation of Privilege | accidental trust via a single click | mitigate | `DestructiveConfirmDialog` with exact-match gating, destructive-filled confirm button, and the API's own `CONFIRMATION_MISMATCH` as the enforced check |
| T-5-89 | Spoofing | generic banner hiding a host-key change | mitigate | `deriveDetailState` returns `host-key-changed` regardless of history and the page renders only the dedicated banner for that code; the E2E asserts the generic copy is absent |
| T-5-90 | Information Disclosure | server data in client storage | mitigate | Only a per-server marker key is stored; a comment and a unit assertion keep fingerprints and hostnames out of storage |
| T-5-91 | Elevation of Privilege | auto-connect after trusting | mitigate | No connect request is issued after a successful trust; PENDING offers Connect as an explicit user action (grep-asserted and E2E-asserted) |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
