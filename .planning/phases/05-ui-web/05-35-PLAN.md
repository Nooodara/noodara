- `ls apps/web/src/app/` returns `(shell)`, `api`, `globals.css`, `layout.tsx`, `login`, `setup`. There is no `page.tsx` at `apps/web/src/app/` and `find apps/web/src -name middleware.ts` returns nothing. An authenticated admin who types the bare origin gets a 404.
- `packages/ui/src/ThemeToggle.tsx` initialises with `useState<Mode>(() => readStoredTheme() ?? 'system')`. The rendered `aria-label` (`Theme: System` vs `Theme: Dark`) and the icon therefore differ between server and client markup for every user who has ever set a preference.
- `apps/web/src/app/(shell)/layout.tsx:28` calls `void requireSession()` once on mount. `require-session.ts` performs one `GET /api/config` with a 5000ms `Promise.race` timeout and redirects only if that one call returns `unauthorized`. Nothing re-checks afterwards.

Purpose: UI-01/UI-02 cover the shell and its screens; a 404 at the origin, a hydration warning on every load, and a tab that silently keeps a revoked session on screen are all defects in that surface. None is exotic.
Output: a root route, a hydration-safe toggle, and a revocation path that actually fires.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated visitor → `/` | A new route is a new entry point into the app |
| revoked session → an already-rendered protected screen | Stale UI implying access that no longer exists |
| `localStorage` theme value → rendered markup | Storage is user/extension-writable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5G-35-01 | Elevation of Privilege | the new `/` route bypassing the auth redirect | mitigate | `/` redirects into `/servers`, which is already behind `proxy.ts`'s server-side check and the backend's `requireSession` hook; E2E asserts the unauthenticated path ends at `/login`. No new authorization logic is introduced. |
| T-5G-35-02 | Spoofing | a revoked session's tab still showing protected data | mitigate | Post-mount re-check driven by the real backend 401 / stream close; redirect carries the current path for return-after-login |
| T-5G-35-03 | Denial of Service | a redirect loop or a request storm from repeated re-checks | mitigate | At-most-once redirect per revocation, asserted by unit test; no polling interval added unless justified |
| T-5G-35-04 | Spoofing | a transient network blip logging the admin out | mitigate | `NETWORK_ERROR` explicitly does not redirect; asserted by unit test. The `withTimeout` fail-closed trade-off is decided consciously and documented, not silently. |
| T-5G-35-05 | Tampering | a foreign/extension-written `noodara-theme` value | accept | Existing behaviour preserved: only the two literals the component itself writes are accepted back, anything else falls back to `system` |
| T-5G-35-06 | Information Disclosure | the redirect target carrying a sensitive path/query | accept | `redirectToLogin` already `encodeURIComponent`s `pathname + search`; no protected path in this app carries a secret in its query (the `/setup` token case is handled by plan 05-30 and `/setup` is not behind this guard) |
