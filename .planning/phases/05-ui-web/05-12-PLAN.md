The SSE producer contract this consumer must match exactly (read from source, not assumed):

`apps/control-plane/src/events/sse-broadcaster.ts` writes named frames: `event: {type}\ndata: {json}\n\n`, so the client must register `addEventListener(type, ...)` per type — a generic `onmessage` never fires for named events. Allowlisted types after Plan 05-04: `server.updated` (payload `{ type, server: ServerView }`), `server.deleted` (`{ type, id }`), `server.discovery_progress` (`{ type, serverId, check }`).
`apps/control-plane/src/routes/events.ts` writes `retry: 5000` as the first bytes, sends `: keepalive` comments every 15s (invisible to `addEventListener`), holds no history and never honours `Last-Event-ID`, closes the stream server-side when its periodic session re-validation fails, and answers `503 SSE_LIMIT_REACHED` with a `Retry-After` header before opening when the connection cap is reached.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Redis-originated SSE frame → browser state | Any writer to the shared channel could try to influence rendered state |
| session expiry → still-open stream and still-rendered data | A revoked session must not keep showing live-looking data |
| `localStorage` theme value → DOM attribute | Only presentational, but still untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-50 | Tampering | received SSE frames | mitigate | Client-side second allowlist: `isKnownEventType` plus `parseServerEventFrame` reject unknown types, type/payload mismatches, malformed JSON and unknown check ids — defence in depth over the server's `KNOWN_EVENT_TYPES` |
| T-5-51 | Elevation of Privilege | stale stream after sign-out | mitigate | `SignOutButton` closes the `EventSource` before calling sign-out; the hook also closes on unmount |
| T-5-52 | Information Disclosure | stale data presented as live | mitigate | `StreamStatus` indicator whenever disconnected, plus a full resync fetch on every `open`; no replay is ever requested |
| T-5-53 | Broken Access Control | a screen reachable without a session | mitigate | `require-session.ts` redirects to `/login` on any `unauthorized` failure; E2E asserts the redirect both before and after sign-out |
| T-5-54 | Denial of Service | reconnect storm against `SSE_LIMIT_REACHED` | mitigate | No custom reconnect loop (the browser honours the server's `retry` field) and an explicit backoff for repeated pre-open failures |
| T-5-SC | Tampering | npm installs | mitigate | No new packages; `lucide-react` was installed and provenance-checked in Plan 05-06 |
</threat_model>
