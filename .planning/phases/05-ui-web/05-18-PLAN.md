</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote command output → `check.detail` → rendered DOM | The most attacker-influenced string on the detail screen |
| SSE progress frames → checklist state | A forged frame could claim a check passed |
| a previous run's stored results → a live run's display | Showing stale results as current would misrepresent the state of real infrastructure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-80 | Spoofing | stale results shown as live progress | mitigate | `buildChecklist` ignores the settled argument entirely while CONNECTING, proven by a dedicated unit test and an E2E regression test; the in-progress caption tells the user why the checklist reset |
| T-5-81 | Tampering | XSS via `check.detail` | mitigate | React escaping; zero `dangerouslySetInnerHTML` in these components (repo-wide gate in Plan 05-21); `detail` was already redactor-passed server-side |
| T-5-82 | Tampering | forged `server.discovery_progress` frame | mitigate | Client-side validation in Plan 05-12 rejects unknown check ids and malformed payloads; every reconnect resyncs from the read endpoint, so a forged check cannot survive a settle |
| T-5-83 | Spoofing | a real failure presented as harmless | mitigate | §4.2's severity table is a named constant list; a `fail` outside the four usable-despite-failure ids renders red, and the E2E asserts the amber case explicitly |
| T-5-84 | Information Disclosure | `durationMs`/`detail` revealing infrastructure internals | accept | This is the product's core value (an honest discovery narrative) shown only to the authenticated single admin about their own servers |
| T-5-85 | Denial of Service | job polling | mitigate | No polling path exists; the E2E asserts no request URL contains `/jobs/`, enforcing phase-4 D-08 |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
