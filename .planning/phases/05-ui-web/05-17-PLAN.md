<interfaces>
Request bodies (verified against `apps/control-plane/src/routes/server-schemas.ts`, 2026-09-19 — all `.strict()`, so an extra key is a 400):

`POST /api/servers` with `{ name, host, sshPort?: number, sshUser?: string, credential }` returns 201 `ServerView`.
`PATCH /api/servers/:id` takes the same fields, every one optional.
`credential` is a discriminated union on `type`: `{ type: 'ssh_private_key', privateKey, passphrase? }` or `{ type: 'ssh_password', password }`. Both variants are `.strict()`; `passphrase` and `password` must be non-empty when present.
`DELETE /api/servers/:id` with body `{ confirmName: string }` returns 200 `{ ok: true, serverId }`; a wrong name is `CONFIRMATION_MISMATCH`.
`POST /api/servers/:id/connect` returns 202 `{ server, jobId }`; `jobId` is for correlation only and must never be polled.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → browser memory → JSON request body | The private key's whole journey; every detour (URL, storage, log, multipart) is a leak |
| browser password manager → credential inputs | Autofill treating an SSH credential as a website login |
| user intent → irreversible delete | A misclick destroys a server record and its credential |
| edit form → stored credential | A pre-filled credential field would expose a stored secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-73 | Information Disclosure | credential in a URL, storage or console | mitigate | Grep gates over all three components plus an E2E assertion that neither storage holds the submitted secret and that no history entry contains it |
| T-5-74 | Information Disclosure | multipart upload of a private key | mitigate | `FileReader.readAsText` only; the E2E asserts every request's content type is JSON and none is multipart |
| T-5-75 | Information Disclosure | credential pre-filled on edit | mitigate | Edit mode renders dots plus Replace and starts from an empty value; the E2E asserts the key's text is absent from the DOM |
| T-5-76 | Information Disclosure | browser autofill saving an SSH credential | mitigate | `autoComplete="off"` on every credential input, grep-asserted |
| T-5-77 | Elevation of Privilege | accidental delete | mitigate | Type-the-name gate via the tested `isConfirmationMatch`, with the API's `CONFIRMATION_MISMATCH` as the enforced check and an inline error slot |
| T-5-78 | Tampering | extra keys in a strict request body | mitigate | Explicit key assignment in `server-form.ts` with a key-set unit assertion; no whole-state spread |
| T-5-79 | Information Disclosure | residual credential from the unselected branch | mitigate | The builder emits only the selected branch's keys, asserted by a dedicated unit test |
| T-5-SC | Tampering | npm installs | mitigate | No new packages in this plan |
</threat_model>
