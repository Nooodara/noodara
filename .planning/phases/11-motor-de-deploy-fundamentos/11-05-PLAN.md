Critical fact (read before writing SQL): `drizzle-orm` 0.45.2's `PgDialect.migrate` (node_modules/.pnpm/drizzle-orm@0.45.2*/node_modules/drizzle-orm/pg-core/dialect.js lines 44-72) executes ALL pending migrations inside ONE `session.transaction`. A fresh install therefore runs 0000..0005 in a single transaction. PostgreSQL forbids using an enum value added by `ALTER TYPE ... ADD VALUE` in the transaction that added it ("unsafe use of new value"). Consequently 0005 — and every future migration — must never reference `git_deploy_key`, `git_https_token` or `registry_password` (no CHECK, DEFAULT, INSERT or index predicate using them). Values of enum types created by `CREATE TYPE` in the same transaction (deployment_status etc.) are safe to use in the partial index predicate.
</objective>
