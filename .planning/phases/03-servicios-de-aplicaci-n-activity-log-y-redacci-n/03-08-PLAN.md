<objective>
DISC-03 and the heart of this phase: `connectAndDiscover` — the single entry point phase 4's
`connect-server` job and DISC-05's re-run will both call.

Purpose: this is where the state machine, the SSH adapter, the credential envelope, the append-only
snapshot, the denormalized server row and two audit events all have to line up inside one coherent
operation without ever leaking a secret or inventing a status.

Transaction shape (load-bearing): SSH work cannot be held inside a database transaction. The service
uses exactly two transactions —
  TX1: `SELECT ... FOR UPDATE`, the D-05 conflict check, `transition(..., 'CONNECTING')` and its UPDATE;
  (SSH connect + discovery + session close happen between them, in no transaction);
  TX2: `applyConnectionResult`, fingerprint timestamps, the optional D-02 second transition, the
       snapshot insert, the denormalized UPDATE and both activity events — all atomic (D-07).

Output: `connect-and-discover.ts` and its integration suite driven by a fake `SshPort` (a real sshd
container exercises the same path end-to-end in plan 03-10).

Observed behaviour of runDiscovery that the D-02 mapping depends on (read directly from
packages/ssh/src/run-discovery.ts, lines ~384-446):
  - exceeding the total discovery budget adds 'COMMAND_TIMEOUT' to `snapshot.warnings` and marks
    every remaining step 'skipped'
  - an unsupported OS adds 'UNSUPPORTED_OS' to `snapshot.warnings`
  - a per-command rejection (including the adapter's classified CONNECTION_LOST) becomes a check
    with status 'fail'; it does NOT add a warning code
  Therefore the service's D-02 mapping is, in order:
    1. warnings contains 'COMMAND_TIMEOUT'        -> CONNECTED -> ERROR,       last_error_code 'COMMAND_TIMEOUT'
    2. classifySnapshotOutcome(checks) === 'failed' -> CONNECTED -> UNREACHABLE, last_error_code 'CONNECTION_LOST'
    3. warnings contains 'UNSUPPORTED_OS'         -> stays CONNECTED,          last_error_code 'UNSUPPORTED_OS'
    4. otherwise                                   -> stays CONNECTED,          last_error_code null
