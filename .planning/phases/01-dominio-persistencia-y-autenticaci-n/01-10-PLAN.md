<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `/api/auth/*` | Unauthenticated, internet-reachable; carries plaintext passwords and session cookies |
| Better Auth → `sessions` / `accounts` tables | Session state and password hashes live here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-25 | Spoofing | Session cookie | mitigate | `HttpOnly` blocks JS exfiltration, `Secure` blocks plaintext transmission and is only removable via the explicit `NOODARA_COOKIE_INSECURE` flag (never from `NODE_ENV`), `SameSite=Lax` limits cross-site submission (AUTH-05, D-08) |
| T-1-26 | Spoofing | Session fixation | mitigate | Sign-in mints a new session id rather than adopting a presented one; asserted by a two-sign-in rotation test |
| T-1-27 | Information Disclosure | Sign-in request logging | mitigate | `routes/auth.ts` never logs the request or reply object; pino `redact.paths` from Plan 01-03 covers `req.body.password` and `req.headers.cookie` as a second layer (RESEARCH Anti-Patterns) |
| T-1-28 | Elevation of Privilege | Password storage | mitigate | argon2id via the `argon2` native bindings replaces Better Auth's default hasher; a test asserts the stored hash begins `$argon2id$` (OWASP Password Storage guidance, STACK.md) |
| T-1-29 | Repudiation | Logout that only clears the cookie | mitigate | The logout test asserts the `sessions` row is deleted, not merely that the cookie was cleared (AUTH-03: "invalidada en el servidor") |
</threat_model>
