<objective>
Make the control plane actually bootable through its own documented commands.

`01-VERIFICATION.md` found one BLOCKER: `pnpm dev` (`node --watch --experimental-strip-types src/server.ts`) and `node apps/control-plane/dist/server.js` both crash with `ERR_MODULE_NOT_FOUND` before INST-06's fail-fast validation ever runs. Two independent causes:

1. Plain Node's type stripping does not remap a `./env.js` relative specifier onto the sibling `env.ts` — and `.js`-specifier NodeNext imports are this codebase's convention everywhere.
2. `packages/domain`'s `exports` map points straight at `.ts` sources with no build step, so even the *compiled* `apps/control-plane/dist` output cannot resolve `@noodara/domain` under plain Node.

The chosen mechanism (see `docs/adr/0003-...` in Plan 01-17) is **both halves of the fix, weighted toward the production path**: `packages/domain` gets a real `tsc` build and its `exports` move to `dist/*.js` + `.d.ts`, so `node dist/server.js` works with zero tsx involvement and the phase-6 Docker image never has to ship a TypeScript loader; `dev` moves to `tsx watch`, which is already a control-plane devDependency and already the loader behind `db:migrate` and the operator CLI.

Purpose: the roadmap's phase-1 goal literally claims "el control plane arranca". Today it only starts inside Vitest.
Output: a green `pnpm build && pnpm start`, a green `pnpm dev`, and a child-process integration test that would have caught this.
</objective>
