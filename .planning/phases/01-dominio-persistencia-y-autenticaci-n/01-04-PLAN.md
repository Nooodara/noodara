<feature>
  <name>Server connection state machine (SERV-05, D-13, D-14, D-15, D-16)</name>
  <files>packages/domain/src/server/server-state.ts, packages/domain/src/server/server-state.test.ts, packages/domain/src/server/connection-result.ts, packages/domain/src/server/connection-result.test.ts</files>
  <behavior>
    Six states: PENDING, CONNECTING, CONNECTED, DISCONNECTED, UNREACHABLE, ERROR. No state is terminal. Allowed edges, extended from the noodara-domain-model table with D-14 and D-15:
    PENDING → CONNECTING; CONNECTING → CONNECTED | UNREACHABLE | ERROR; CONNECTED → CONNECTING | DISCONNECTED | UNREACHABLE | ERROR | PENDING; DISCONNECTED → CONNECTING; UNREACHABLE → CONNECTING; ERROR → CONNECTING | PENDING.
    Three edges require an explicit reason: CONNECTED → PENDING (`identity_changed`, D-14), ERROR → PENDING (`fingerprint_trusted`, D-15), CONNECTED → DISCONNECTED (`clean_close`, D-13).
    Connection results map to one status each: AUTH_FAILED → ERROR, COMMAND_TIMEOUT → ERROR, HOST_KEY_CHANGED → ERROR, UNSUPPORTED_OS → ERROR, HOST_UNRESOLVED → UNREACHABLE, CONNECT_TIMEOUT → UNREACHABLE, CONNECTION_LOST → UNREACHABLE, success → CONNECTED.
  </behavior>
  <implementation>Pure TypeScript plus a frozen lookup table; zero I/O, zero dependencies beyond the module itself.</implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote server SSH result → Noodara persisted state | A hostile or compromised host controls what a connection attempt reports; the mapping must not let it choose an arbitrary state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-07 | Spoofing | `applyConnectionResult` on HOST_KEY_CHANGED | mitigate | A changed host key never overwrites `hostFingerprint`; it lands in `pendingFingerprint` with status ERROR and requires the explicit `fingerprint_trusted` reason to return to PENDING (D-15, PITFALLS.md #4, never `StrictHostKeyChecking=no`) |
| T-1-08 | Tampering | Direct status assignment from any future caller | mitigate | Status is only produced by `transition()`; the exhaustive cross-product test fails if the table is widened, and `applyConnectionResult` is the only exported path from a connection outcome to a status |
</threat_model>
