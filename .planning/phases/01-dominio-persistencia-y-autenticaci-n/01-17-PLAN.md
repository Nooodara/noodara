    Create `docs/adr/0003-runtime-entrypoints-and-module-resolution.md` following the `0002` structure exactly:

    - **Status:** `Accepted — <execution date>`.
    - **Context:** the codebase uses NodeNext `.js` relative specifiers throughout (tsc's own convention). Plain Node's `--experimental-strip-types` does not remap a `.js` specifier onto a sibling `.ts`, and `packages/domain`'s `exports` pointed at `.ts` sources with no build step — so `pnpm dev` and the compiled `dist/server.js` both died with `ERR_MODULE_NOT_FOUND` before INST-06's fail-fast could run. The defect reached the end of phase 1 because every "boot" proof ran through Vitest's transform or through `tsx`.
    - **Decision**, three parts: (1) `packages/domain` builds with `tsc` and its five `exports` entrypoints resolve to `dist/*.js` with `.d.ts` types; (2) production runs `node dist/server.js` (`pnpm start`) with no TypeScript loader in the runtime path — this is what the phase-6 Docker image packages; (3) development runs `tsx watch src/server.ts` (`pnpm dev`), reusing the loader already behind `db:migrate` and the operator CLI. In-process tests keep resolving `@noodara/domain` to `src` through a Vitest `resolve.alias`, because QA-02's 95%/95% threshold is scoped to `packages/domain/**` source and resolving to `dist` would silently zero it.
    - **Rejected alternatives**, each with its reason: rewriting every relative import to `.ts` specifiers (breaks `tsc` emit and the entire NodeNext convention); shipping `tsx` in the production image (a dev loader in the runtime path — extra startup cost and attack surface, against the roadmap's thin-image goal); leaving `exports` on `.ts` and demanding a loader everywhere (guarantees phase 6 inherits the same class of defect).
    - **Consequences:** `lint`, `typecheck` and `dev` now declare `dependsOn: ["^build"]` in `turbo.json`; a clean checkout must build `packages/domain` before typescript-eslint can type `apps/control-plane`; editing domain source during `pnpm dev` needs a rebuild to reach the running process; `dist` is self-contained (migrations copied in, test files excluded); `boot-smoke` in CI is the standing regression gate.
