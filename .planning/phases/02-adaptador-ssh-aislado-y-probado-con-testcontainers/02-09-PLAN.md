<objective>
Turn one open session into a `DiscoverySnapshot`: eleven allowlisted commands, eleven separately-reported checks, and partial results that survive any single failure.

Purpose: DISC-04 and D-11/D-12/D-13 all say the same thing in different words — a discovery run degrades, it does not fail. An unsupported OS, a missing Docker, a non-root user without sudo and a check that times out are four different partial outcomes, and in every one of them the operator still gets the facts that were collectable plus a precise reason for the rest. This is also the structure phase 5's step-by-step narrative (DISC-02) renders without transformation, so the shape matters as much as the values.
Output: `run-discovery.ts` and the finished public surface of `@noodara/ssh`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote command output → `DiscoveryFacts` → UI and future deploy decisions | Every fact originates on an untrusted machine and will be displayed to the operator and, from v0.2, used to decide whether a deploy may proceed |
| `runDiscovery` → worker (phase 4) | A rejection or an unbounded run inside discovery stalls or crashes the job that invoked it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-37 | Denial of Service | A discovery run with no overall bound | mitigate | Elapsed time is checked against `timeouts.discoveryMs` before every command; an overrun aborts, returns partial facts, and records `COMMAND_TIMEOUT` in `warnings` (D-08) |
| T-2-38 | Denial of Service | One failing check aborting the whole run | mitigate | Each sequence iteration is independently guarded; a failure becomes a `fail` check with a detail and the loop continues, and `runDiscovery` never rejects |
| T-2-39 | Tampering (of trust in reported state) | `dockerInstalled` derived from an unparseable result | mitigate | `unparseable` leaves `dockerInstalled` null and is asserted to never be `false`; only a measured `not_installed` sets `false` (D-12, Pitfall 2) |
| T-2-40 | Tampering (of trust in reported state) | An unsupported OS silently reported as fine, or as broken | mitigate | `UNSUPPORTED_OS` in `warnings` with the check still `pass`: the operator sees a working server carrying an explicit platform warning, which is DISC-04's exact requirement |
| T-2-41 | Information Disclosure | A credential echoed into a check's detail via stderr | mitigate | Details are passed through the injected `Redactor`, on top of `exec` having already redacted stdout/stderr; a test scripts a registered secret into stderr and asserts no detail contains it (SEC-05) |
| T-2-42 | Elevation of Privilege | A phase-3 service reaching past `SshPort` into adapter internals | mitigate | `index.ts` exports a deliberate surface asserted by a literal export-name test; internals and `src/testing/` are unreachable through the package's single `.` entrypoint |
</threat_model>
