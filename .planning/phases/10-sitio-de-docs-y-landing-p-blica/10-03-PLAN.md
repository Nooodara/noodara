<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions marketplace → CI runner | Third-party actions execute with a job token |
| CI → GitHub Pages | The deploy job holds an OIDC token and pages:write |
| PR author → CI | PR code runs the site build in the `site` job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering | uses: lines in public-site.yml / ci.yml | high | mitigate | 40-hex SHA pins with tag comments, verified live via gh api; scanWorkflowPins assertion in check-workflow-pins.test.ts |
| T-10-02 | Elevation of privilege | workflow token scopes | high | mitigate | Top-level `permissions: {}`; build job contents:read only; deploy job pages:write + id-token:write only; ci.yml site job contents:read; asserted by tests |
| T-10-10 | Spoofing/Tampering | Pages deployment | high | mitigate | Publish only on push to main (no pull_request trigger, asserted); `github-pages` environment; concurrency group pages with no cancel mid-deploy |
| T-10-03 | Information disclosure | build logs / artifact | medium | mitigate | public-site.yml references no `secrets.` (asserted); the site build reads no secret env; artifact is only apps/site/out |
| T-10-16 | Tampering | release pipeline coupling | medium | mitigate | Tests assert release.yml and docker-compose*.yml never mention the site (D-13) |
| T-10-17 | Spoofing | DNS takeover of noodara.com while Pages is not yet configured | low | accept | Operator-controlled DNS; README orders "configure Pages custom domain, then DNS"; GitHub verifies the domain before issuing TLS |
</threat_model>
