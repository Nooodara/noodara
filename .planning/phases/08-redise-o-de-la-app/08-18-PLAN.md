<objective>
Build the phase's first authored moment: the discovery narration. Six steps on a thread that fills as the server is understood, each with its real duration, and the brand's own aperture ring coming into focus alongside them — tied to the actual run, so a failed run leaves it unfinished. The same focusing animation greets the user once on `/login` and `/setup`.

Purpose: UI-08 and brief §8.4. This is the thing Coolify and Dokploy do not have, and the brand-swap test is how the user judges it at G3. Phase 7 built the `data-part="aperture"` hook specifically for this plan.
Output: `aperture.css`, a timeline-with-thread discovery section, a focusing ring, and a one-shot focus on the auth screens.
</objective>

| T-08-48 | Spoofing | Viewfinder ring as a progress signal | mitigate | The ring's only input is the completion fraction derived from `buildChecklist`; there is exactly one computation, no easing toward completion, and no timer — a partial run leaves it partial, asserted by a dedicated E2E case |
| T-08-49 | Information Disclosure | discovery step captions | mitigate | Durations are numbers formatted by a pure function; no server-supplied text is rendered raw and the closed error-code vocabulary is untouched (§9 #17) |
| T-08-37 | Information Disclosure | step state signalling | mitigate | `STATE_WORDS` keeps the status word in each step's text content; the thread and ring add signal, never replace it (§9 #14) |
| T-08-50 | Denial of Service | check stagger under a burst of SSE checks | mitigate | The delay is index-derived and capped, applied as a CSS transition with no JS timers, and never sets `pointer-events: none` |
| T-08-SC | Tampering | npm installs | accept | No package is installed; the ring is CSS only — `motion` stays confined to `Sheet` per D19 |
