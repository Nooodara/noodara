came out of `bootstrap-admin.ts`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator environment → install.sh → .env → container | `NOODARA_ADMIN_PASSWORD` travels from a shell environment through a file on disk into the argon2 hashing path |
| api container logs → installer stdout | the setup token is deliberately plaintext on exactly one path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Information Disclosure | generated secrets or the pre-seed password reaching stdout/stderr/install.log | mitigate | Both scenarios run a canary assertion over the real captured streams and the real `install.log`, using the actual generated values read back out of the fixture — the same discipline as `tests/integration/activity/canary.test.ts`, now applied to the installer. |
| T-06-45 | Spoofing | the installer printing a token that is not the one the api issued | mitigate | The fresh-install scenario asserts byte equality between the installer-printed token and the token in the api container's own logs; a fabricated or stale value fails the test. |
| T-06-51 | Information Disclosure | `NOODARA_ADMIN_PASSWORD` persisting in `/opt/noodara/.env` after the admin exists | accept | `env.ts` requires the pair to be both-or-neither and `bootstrap-admin.ts` consumes it at every boot; removing it after first use would make a container restart fail INST-06's validation. The file is mode 600, root-owned, and `docs/install.md` (Plan 06-14) documents that an operator may remove both variables once the admin is created. Residual risk accepted and documented, not hidden. |
| T-06-52 | Spoofing | a pre-seeded admin that cannot actually authenticate, leaving the operator locked out with no token | mitigate | The scenario proves login works through the real proxy, not merely that a user row exists. |
| T-06-48 | Tampering | privileged fixture containers surviving a failed run | mitigate | Idempotent `stop()` in `finally`, `assertNoStrayTestContainers()` in `afterEach`, and the existing CI stray-container step. |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No new package. |
</threat_model>
