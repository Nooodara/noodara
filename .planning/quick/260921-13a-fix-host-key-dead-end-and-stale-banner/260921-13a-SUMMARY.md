## Decisions Made
- `derivePrimaryAction`'s fallback condition is `lastErrorCode === 'HOST_KEY_CHANGED' && pendingFingerprint !== null`, exactly as the plan's interfaces section specified — no alternative shape considered, since the backend's `ERROR -> CONNECTING` transition and TOFU-on-null-hostFingerprint behavior were already proven by prior phase-05 work.
- The banner's calm-copy gate uses both fingerprints (`hostFingerprint === null && pendingFingerprint === null`), not just `pendingFingerprint === null`, because a null `pendingFingerprint` alone is also reachable via `NO_PENDING_FINGERPRINT` after a successful trust promote (WR-01's own fix) — that state has a real `hostFingerprint` to show, so it must keep the original copy and rows. Only the CR-01 identity-changing-edit state (both null) gets the new copy.
